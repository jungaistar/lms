# 상호평가 학습관리시스템

전문대 수업에서 학생들이 **서로의 발표·토론·팀 기여·과제를 평가**하고,
그 결과를 집계해 **학교 LMS 성적으로 넘기는** 시스템입니다.

📖 **가이드 사이트**: https://lms.miraejob.co.kr
(도메인 연결 전 주소는 https://jungaistar.github.io/lms/ 였습니다 — `docs/60-domain.md`)

---

## 무엇을 하는가

지금 **홈에 내걸고 운영하는** 평가는 두 가지입니다.

| 활동 | 학생이 하는 일 | 점수가 나오는 방식 |
|---|---|---|
| **발표 상호평가** | 발표 조를 루브릭으로 채점 + 코멘트 | 받은 점수 평균 (극단값 제외) |
| **팀 기여도 평가** | 팀원에게 100점 배분 | 균등 배분 대비 기여 배율 |

시스템은 **토론 참여 평가**와 **과제 동료 첨삭**도 그대로 지원합니다.
홈에서만 내렸을 뿐이라 교수 화면에서 활동을 만들면 바로 쓸 수 있고,
다시 내걸려면 `web/src/pages/Landing.tsx` 의 `ACTIVITIES` 에 줄을 되살리면 됩니다.

네 활동 모두 **미평가 감점**이 붙습니다. 남을 평가하지 않으면 자기 점수도 깎입니다.

상호평가만 하는 게 아니라 **수업 운영 전체**를 다룹니다 — 주/회차, 공지, 자료,
과제, 설문, 출석, 기타(감점), 성적 산출까지. 교수 화면은 왼쪽 세로 메뉴로 묶여
있습니다 → [docs/50-admin-console.md](docs/50-admin-console.md)

### 기타 점수 (지각 · 결석 · 태도 · 과제)

지각·조퇴·결석은 출결에서, 과제 미제출·지각 제출은 과제에서 **자동으로 셉니다.**
수업 태도처럼 셀 근거가 없는 것만 **수업 중 체크** 화면에서 그 자리에 누릅니다.
학교 LMS 에 낸 과제 현황은 표를 긁어 붙이면 반영됩니다. 기말에 성적 산출을
한 번 누르면 전부 기타 점수로 들어갑니다.

## 공개 정책

- 학생은 **자기가 받은 코멘트만** 봅니다. 누가 썼는지는 표시되지 않습니다.
- **점수는 학생에게 공개되지 않습니다.** 화면에서 감추는 게 아니라, 점수를 반환하는
  API 자체가 학생 토큰에 존재하지 않습니다 (`docs/20-assessment-design.md` 참조).
- 교수는 누가 누구에게 몇 점을 줬는지 전부 봅니다.

## 구조

```
web/       학생·교수 화면 (React + Vite → GitHub Pages)
supabase/  DB 스키마 · RLS 정책 · 집계 함수 · 학생 로그인 Edge Function
bridge/    학교 LMS(*.dunet) 연동 — 명단 가져오기, 성적 넘기기
docs/      설계 문서와 설치·운영 가이드
```

데이터와 권한 통제는 전부 Supabase(Postgres + RLS)에 있습니다.
프론트엔드는 정적 파일이라 서버 운영이 필요 없습니다.

## 계정 구조

| 역할 | 들어오는 방법 | 할 수 있는 것 |
|---|---|---|
| **관리자** | 지정된 이메일로 회원가입 (자동 승인) | 회원 승인·정지, 회원 목록 |
| **교수** | 회원가입 → 관리자 승인 | 자기 과목의 모든 것 |
| **학생** | 이메일 + 학번 + 이름 → 명단 대조 → 교수 승인 (가입 없음) | 배정받은 평가, 받은 코멘트 |

관리자 이메일은 DB의 `admin_email()` 함수에 하드코딩되어 있습니다.
프론트를 고쳐도 권한은 넘어가지 않습니다 — RLS가 JWT의 email을 직접 봅니다.

승인 대기 상태에서는 **과목을 만들 수 없습니다.** 화면에서 버튼을 감추는 게 아니라
`courses` INSERT 정책이 `is_approved()` 를 요구하기 때문입니다.
관리자도 남의 수업 안의 평가·점수는 볼 수 없습니다 — 회원과 그 규모까지만 봅니다.

## 시작하기

1. **Supabase 프로젝트를 만들고 스키마를 올립니다** → [docs/10-setup.md](docs/10-setup.md)
2. `web/.env` 에 URL과 anon key를 넣고 `npm run dev`
3. 관리자 이메일로 **회원가입** → 과목 만들기 → 명단 붙여넣기 → 루브릭 → 활동 만들기
4. 과목마다 **입장 승인 → 명단 전원 승인**을 한 번 눌러 둡니다
5. 학생은 홈에서 자기 수업을 누르고 **이메일 · 학번 · 이름**으로 들어옵니다

학기 중 실제 운영 순서는 [docs/30-operations.md](docs/30-operations.md)에 있습니다.
작업 이력은 [docs/90-worklog.md](docs/90-worklog.md)에 날짜순으로 남깁니다.
**지금 어디까지 왔는지**는 [docs/00-status.md](docs/00-status.md) — 측정해서 적은 점검표입니다.

## 학생 로그인

**이메일 + 학번 + 이름**을 넣으면 교수가 올린 명단과 대조하고,
**교수가 승인한 뒤에** 들어옵니다. 가입 절차는 없습니다.

승인 뒤에는 그때 넣은 **이메일로만** 들어올 수 있습니다 — 승인 후의 두 번째
열쇠입니다. 학기 초에 `입장 승인 → 명단 전원 승인`을 한 번 눌러 두면 학생은
기다리지 않고, 첫 로그인 때 이메일이 묶입니다.

옛 **수업코드 + 학번** 방식은 `courses.entry_mode = 'code'` 인 과목에서만
통합니다. 수업코드는 한 번 새어 나가면 막을 방법이 없어 기본에서 뺐습니다.

자세한 내용은 [docs/50-admin-console.md](docs/50-admin-console.md#입장-승인-2026-08-12-추가),
로그인의 한계와 대응은
[docs/20-assessment-design.md](docs/20-assessment-design.md#로그인의-한계)에 있습니다.

## ⚠️ 학교 LMS 연동 전 확인

`bridge/` 는 학교 LMS(BLU 3.0 계열)를 다룹니다. 쓰기 전에:

- 접속 대상이 운영 시스템인지 확인하세요 (조사 당시 화면에 "Demo" 표기가 있었습니다).
- 운영이라면 **소속 기관에 자동화 도구 사용이 허용되는지 먼저 문의**하세요.
- 성적 입력 화면의 셀렉터는 아직 확인하지 못해 `SELECTORS_VERIFIED = false` 로 잠겨 있습니다.
  그 전까지는 CSV를 내려받아 화면에서 직접 입력하세요.
