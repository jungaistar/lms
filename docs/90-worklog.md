## 2026-08-29 — 주차별 명단 · 출석 · 과제 화면에 전화번호

### 넣은 것

- **주차별 명단** (`수업 운영 → 주차별 명단`) — 1~15주차 가운데 하나를 고르면
  그 주의 **과제 미제출 · 지각 제출 · 결석 · 지각**을 한 화면에 모으고 줄마다
  **전화번호**를 붙인다. 연락 대상만 추린 표를 CSV · XLSX · 인쇄로 내보낸다
- **출석 관리 · 과제 채점** 표에 **전화번호 열** 추가 — 결석·미제출을 보는 그
  자리에서 바로 연락할 수 있게. 팀 과제 줄에는 붙이지 않는다

### 출결 미기록을 결석과 섞지 않는다 — 이번 작업의 핵심

`attendance` 에 줄이 없는 것은 두 가지다. **아직 출석을 안 부른 회차**와
**결석**. 이 둘을 합치면 출석을 안 부른 주차의 명단 전원이 결석자로 나오고,
그 명단으로 학생에게 연락하면 한 번에 신뢰를 잃는다.

그래서 `unmarked` 를 `absent` 와 별도 상태로 두고 —

- 현황판에 **출결 미기록**을 따로 센다
- 연락 대상(`needsContact`)에 넣지 않는다
- 내보내는 파일에도 넣지 않는다
- 대신 "안 부른 칸이 N개 있습니다" 를 띄우고 출석 관리로 보낸다

과제 쪽 판정도 같은 이유로 순서를 고정했다. 학교 LMS 가 알려 준 `ext_state` 가
있으면 그것을 먼저 믿고, 없을 때만 `submitted_at` 유무로 가른다 — 우리가
마감시각을 잘못 넣었을 때보다 학교 쪽 판정이 정확하다.

### 왜 화면과 떼어 놨나

판정 규칙을 `web/src/lib/weekly.ts` 에 순수 함수로 두고
`web/test/weekly.check.ts` 로 24가지를 시험한다. 위의 경계(미기록 vs 결석,
`ext_state` vs `submitted_at`, 공결·조퇴는 연락 대상이 아님)는 화면 안에 있으면
눈으로 볼 수밖에 없다.

### 아직 남은 것

- **전화번호가 0건이다.** 학교 LMS `학생별 과제` 의 핸드폰 칸은 전원 공란이고,
  대시보드 `연락처 관리` 도 비어 있다. 헤이영
  `UMS시스템 → 푸시 → 푸시 전송 → 수신자 추가` 에서 `개인정보마스킹여부` 를 끄고
  긁어 붙여야 이 화면의 번호 칸이 채워진다 ([`70-attendance-contacts.md`](70-attendance-contacts.md))
- `npm test` 의 `roster-files.check.ts` 는 이 작업 **이전부터** 3개 파일이
  실패한다(`*_202620.tsv` 의 머리글 줄 · 학년 칸). 이번 변경과는 무관하다

## 2026-08-23 — 연락처(전화번호) · 일자별 기록 · 문자 · 알림

`0012_contacts_daily_marks.sql` · `0013_messaging.sql`.
자세한 것은 [`70-attendance-contacts.md`](70-attendance-contacts.md).

### 넣은 것

- **연락처 관리** — 헤이영 엑셀다운 파일 올리기 + 마스킹 푼 줄 붙여넣기.
  표에서 바로 고칠 수도 있다. 가입 이메일도 함께 보여 준다
- **일자별 기록** — 날짜(회차) 하나를 펴 놓고 한 줄에
  출결 · 수업태도 점수 · 과제 점수 · 메모를 적는다. 누르면 바로 저장, 언제든 수정
- **문자 · 알림** — 대상 거르기(그날 결석 · 누적 결석 · 번호 없는 사람 …) →
  문안 만들기 → 헤이영 문자발송용 번호 목록 / 기기 문자앱 · 메일 · 공유 시트

### 표를 왜 갈랐나 — 이번 작업의 핵심

`students` 에 `phone` 을 붙이려다 멈췄다. 그 표에는 `student_peer_read` 가 있어
**같은 반 학생이 명단 전체를 읽는다.** 번호를 붙였으면 학생 하나가 로그인만으로
반 전체 번호를 가져갔을 것이다. 화면에서 감춰도 PostgREST 에 직접 요청하면 나온다.

같은 이유로 수업태도·과제 점수도 `attendance` 에 못 넣는다 —
거기엔 '본인 것만 읽기' 정책이 있어서 학생이 자기 태도 점수를 읽게 된다.

그래서 `student_contacts` 와 `session_marks` 를 따로 만들고
**학생용 RLS 정책을 아예 만들지 않았다.**

### 확인

로컬에 Postgres 16 을 띄워 `0001`~`0013` 을 순서대로 올리고 실제로 시험했다.

- 교수 둘 · 과목 둘로 격리 확인 — 남의 교수는 연락처 · 일자별 기록 · 보낸 기록을
  **0줄** 읽고, `session_mark_summary()` · `message_targets()` 도 0줄을 낸다
- 학생 토큰으로도 세 표 모두 **0줄**. 명단(`students` 2줄)은 지금까지처럼 보인다
- 명단 밖 학생을 섞어 보내면 **통째로 거부**된다
- 마스킹된 값이 이미 풀어 둔 번호를 **덮지 않는다**
- `unmarked = 'zero'` 로 바꾸면 안 매긴 날이 0점으로 셈에 들어간다

### 밟았던 자리

- `session_mark_summary()` · `message_targets()` 는 `security definer` 라 RLS 를
  건너뛴다. 안에서 `owns_course()` 를 직접 부르지 않으면 **남의 과목 id 를 넣어
  부르는 것으로 명단과 번호가 통째로 샌다.** 처음 판에 그 줄이 없었다
- `<a aria-disabled>` 는 **여전히 눌린다.** 받는 사람 0명인 채로 문자앱이 열려
  보낸 줄 착각하게 된다 — 링크를 아예 안 그리는 쪽으로 고쳤다
- iOS 와 안드로이드의 `sms:` 문법이 반대다(`&body=` / `?body=`).
  틀리면 본문이 통째로 사라진다

### 화면 — 다섯 폭에서 눈으로 확인

360 · 393 · 768 · 1024 · 1440px 에서 실제로 띄워 보고 두 가지를 고쳤다.

- 태블릿에서 수업태도 `0~5` 와 과제 `0~5` 가 붙어 **똑같이 생긴 버튼 열두 개**로
  보였다 → 묶음 사이에 1px 선
- 900px 이하에서 누르는 대상이 전부 40px 이었다 (`.btn-sm` 기본).
  문서에는 "터치 44px" 라고 적혀 있었지만 규칙이 **입력 칸에만** 걸려 있었다
  → 버튼도 44px 로. 이건 기존 화면에도 함께 적용된다

`web/tools/mark-row-preview.html` 을 남겼다 — 교수 화면은 로그인해야 열려서
레이아웃만 따로 볼 자리가 필요했다.

```
npm test      명단 23 · 헤이영 39 · 가로형 31 · 연락처 51 · 문자 50 ·
              내보내기 27 · 학교 LMS 과제 34 · 반응형 25 — 실패 0
npm run build 성공
```

### 남은 것

- `0012` · `0013` 은 아직 **적용 전**이다. Supabase SQL Editor 에서 올려야
  세 화면이 동작한다 (`70-attendance-contacts.md` 6절)
- 헤이영에서 번호를 받아 오는 일은 **사람 손이 남는다.** 마스킹 해제가
  한 명씩이라 그렇다. 이쪽은 "누가 아직 비었는지" 를 표로 보여 주는 데까지다

## 2026-08-20 (주소) — `lms.miraejob.co.kr` 로 옮길 준비

`miraejob.co.kr` 을 Cloudflare 로 연결해 두었다. 앞으로 저장소마다
`<저장소명>.miraejob.co.kr` 을 쓴다. 이 저장소는 `lms.miraejob.co.kr`.

### DNS 를 먼저 읽어 봤다 (2026-08-20)

| 이름 | 값 |
|---|---|
| `miraejob.co.kr` | A `185.199.108~111.153` — GitHub Pages apex 4개 |
| `www` | CNAME `jungaistar.github.io` (프록시 꺼짐) |
| `lms` | **없음 (NXDOMAIN)** — 이것만 없어서 안 떴다 |

apex 와 `www` 는 이미 GitHub 을 가리키는데 `lms` 만 비어 있었다.
와일드카드도 없다.

### 코드에서 고친 것

- `web/public/CNAME` 을 새로 만들었다. Vite 가 `public/` 을 `dist/` 뿌리로 복사한다.
- `vite.config.ts` 의 `base` 를 `/lms/` → **상대 경로 `./`** 로 바꿨다.
  `/lms/` 로 박아 두면 도메인 주소에서 자산이 404 나고, `/` 로 박으면 github.io
  주소가 깨진다. 상대 경로면 **둘 다 그대로 돌아서 갈아끼우는 동안 화면이 안 죽는다.**
  HashRouter 라 문서가 언제나 그 자리 index.html 하나뿐이어서 기준점이 안 흔들린다.
- 반응형 점검 도구가 iframe 주소를 `'/lms/' + route` 로 박고 있었다.
  지금 경로에서 되짚도록 고쳤다 — 안 그러면 도메인 쪽에서 빈 iframe 이 뜬다.
- `index.html` 에 `og:url` · `canonical` 을 넣었다.
- 절차는 `docs/60-domain.md` 에 남겼다.

### 남은 것 — 사람이 눌러야 한다

1. Cloudflare `miraejob.co.kr` → DNS → CNAME `lms` → `jungaistar.github.io`,
   **DNS only(회색 구름)**. 주황 구름이면 GitHub 이 인증서를 못 받는다.
2. 저장소 `Settings → Pages → Custom domain` 에 `lms.miraejob.co.kr` → Save →
   초록불 뒤 `Enforce HTTPS`. **Actions 배포라 `CNAME` 파일만으로는 안 켜진다.**

## 2026-08-12 (명단) — 학교 LMS 에서 6과목 199명 받아 넣기

### 어디서 받았나

학교 LMS 의 **성적산출/결과** 화면
(`/lms/class/courseScoreManage/doListView.dunet`). 한 줄이
`NO · 학과 · 학년 · 학번 · 이름 · 총점 · 가산점 · …` 이다.

주소를 직접 치면 메인으로 튕긴다. 세션에 과목이 얹혀 있어야 열리는 화면이라
`나의 강의실 → 과목 → 성적산출/결과` 를 눌러서 들어가야 한다.

| 과목 | 분반 | 인원 |
|---|---|---|
| 자원관리능력 | Y1 | 34 |
| 1인예술과창업실무 | Y2 | 30 |
| 취업과경력개발 | Y3 | 33 |
| 창업과기업가정신 | Y4 | 34 |
| 문화예술콘텐츠창업 | Y5 | 35 |
| 문화예술콘텐츠창업 | Y6 | 33 |

받은 명단은 `data/roster/*.tsv` 에 둔다. **커밋하지 않는다** — `.gitignore`
의 `data/` 항목이 실제 학생 정보를 막고 있다.

### 파서를 바꾼 이유

전에는 `학번 · 이름 · 팀` 세 칸을 **자리로** 셌다. 학교 LMS 표를 그대로
붙이면 첫 칸이 NO 라서 학번이 "1" 이 되고 이름이 학과가 됐다.

`lib/roster.ts` 로 떼어내고 **생김새로 고르게** 바꿨다.
학번(6자리 이상 숫자) → 이름(`extTasks.pickName`) → 학과(`…과/계열/학부/전공`)
→ 학년 → 남은 칸이 팀. 뒤에 붙는 `점 · 추가점수 저장 · 출석미달` 은 버린다.

밟은 함정 두 개:

- **NO 와 학년이 둘 다 한 자리 숫자다.** 3번 학생의 3학년을 NO 로 읽거나
  그 반대가 된다. 학년은 *학번 바로 앞칸* 이나 *이름 바로 뒷칸* 만 본다.
- 그런데 팀 이름을 `1` `2` 로 적는 경우가 있다. 그래서 맨숫자를 학년으로
  받는 건 **학과 칸이 함께 있을 때만** 이다. 없으면 옛 방식대로 팀이다.

### 학년 · 학과

`0011_student_grade_dept.sql` 로 `students.grade` · `students.dept` 를 넣었다.
팀 편성 때 같은 학과가 몰리지 않게 보려는 것이고, 한 과목 안 동명이인
(박소정 등)을 표에서 바로 가르려는 것이기도 하다.

아직 **적용 전**이라 명단 반영은 두 열을 빼고 들어갔다. RosterTab 이
`PGRST204` 를 받으면 학번 · 이름만으로 한 번 더 넣는다 — 마이그레이션 때문에
명단 넣기가 막히면 안 되기 때문이다. 올린 뒤 다시 붙여넣으면 채워진다.


## 2026-08-12 (심야) — 마이그레이션 적용과 실제 검증

### 마이그레이션이 두 번 실패했던 이유

`0006` · `0007` 의 정책 27개에 `drop policy if exists` 가 없었다.
한 번이라도 부분 적용되면 두 번째 실행이 거기서 멈춘다. 게다가 SQL Editor 는
오류가 나도 앞부분은 이미 반영된 상태로 남는다 — 그래서 다시 돌릴수록
더 일찍 실패했다.

전부 idempotent 로 고치고 `supabase/apply-pending.sql` 한 파일로 묶은 뒤
한 번에 통과했다. 표 18개 API 200 확인.

### 실제로 돌려 보고 고친 것

| 무엇 | 원인 |
|---|---|
| 과목 상단이 "수업코드로 입력합니다" 라고 거짓말 | `entry_mode` 를 안 보고 있었다 |
| 과제 제출현황이 **한 줄도 안 들어감** | 부분 유니크 인덱스에 `upsert` 를 걸었다. Postgres 는 부분 인덱스를 `ON CONFLICT` 근거로 못 쓴다 |
| 그 오류가 "반영하지 못했습니다" 로만 보임 | **Supabase 오류는 `Error` 인스턴스가 아니다.** `e instanceof Error ? e.message : '…'` 가 32곳에서 진짜 이유를 버리고 있었다 |

`lib/errors.ts` 의 `errText()` 로 바꿔 `message · details · hint · code` 를
모아 보여 준다. 23개 파일에 적용했다.

### 검증한 흐름 (실제 DB · 실제 Edge Function)

- 주차 15개 생성 → 감점 항목 6개(결석 포함)
- 수업 중 체크: 지각 1건 → 1.0, 태도 불량 1건 → 2.0
- 과제 제출현황: 마감 비교로 제출/지각/미제출 판정 → 감점 재계산
  (제출 0.0 · 지각제출 3.0 · 미제출+태도 7.0 · 미제출 5.0)
- 학생 로그인 네 갈래 + 승인 뒤 **이메일 잠금**(다른 주소 거절, 원래 주소 입장)

### 검증하다 내가 밟은 함정

"이름이 안 맞는다" 며 오래 헤맸는데 원인은 앱이 아니라 **Windows Git Bash 에서
curl 인자의 한글이 깨져 나간 것**이었다. JSON 을 파일로 만들어
`--data-binary @file` 로 보내면 정상이다. API 를 직접 찌를 때 반복하지 말 것.

## 2026-08-12 (밤) — 홈 화면 정리 · 반응형 자동 검사

### 탭 아이콘에 '직' 이 남아 있었다

헤더·푸터 심볼은 지웠는데 **favicon** 이 남아 있었다. 데이터 URI 안에
`%EC%A7%81` 로 인코딩돼 있어서 코드를 '직' 으로 검색해도 안 잡혔다.
브라우저 탭에서 제목 바로 앞에 붙어 보이던 게 이것이다.
글자 대신 서로 오가는 화살표 두 개로 바꿨다. 그 자리에 글자를 넣지 말 것.

### 평가 활동 = 개설 과목 6개 + 평가 2가지, 한 화면

두 섹션으로 나눠 놨던 것을 합쳤다. 같은 격자에 8장이 놓인다.
과목 카드는 링크(왼쪽 강조 줄 · '들어가기'), 평가 카드는 링크가 아니다
(회색 바탕 · 강조 줄 없음). 눈으로 구분되게 해서 헛눌러 보지 않게 한다.

### 반응형 자동 검사 — `test/responsive.check.ts`

CSS 를 글자로 읽어 규칙이 살아 있는지 본다. 브라우저를 안 띄우므로 CI 에서도 돈다.
이번에 실제로 깨졌던 두 가지를 그대로 잡는다.

- `input:not([type])` 이 선택자에서 빠지면 → 실패
- 900px 이하 `font-size: 16px !important` 가 빠지면 → 실패 (iOS 확대)

그 밖에 viewport meta, 900px 메뉴 전환(세로 ↔ select), 640px 수업 중 체크
두 줄 배치, `.table-wrap` 가로 스크롤, 집계표 첫 열 고정, 격자 auto-fill,
360px 를 넘기는 고정 폭 없음까지 20항목.

**검사를 만들고 나서 일부러 규칙을 지워 실패하는지 확인했다.**
그 과정에서 검사 자체의 결함을 찾았다 — 주석에 적힌 규칙 이름을 보고
통과하고 있었다. 주석을 먼저 걷어내도록 고쳤다.

눈으로 보는 확인을 대신하지는 못한다. 360 · 390 · 768 · 1024 · 1280 에서
직접 열어 보는 절차는 그대로다.

## 2026-08-12 (저녁) — 학생 입장 방식 교체 (수업코드 → 승인)

안내: [`50-admin-console.md` 입장 승인](50-admin-console.md#입장-승인-2026-08-12-추가) ·
적용 순서: [`11-migrate.md` 3-2](11-migrate.md)

### 왜

수업코드는 한 번 새어 나가면 막을 방법이 없다. 단톡방에 올라가면 수강생이
아닌 사람도 학번만 알면 들어온다. 학번은 같은 수업 학생끼리 서로 안다.

### 무엇으로 바꿨나

이메일 + 학번 + 이름 → **명단 대조** → **교수 승인** → 입장.
이메일은 승인 뒤의 **두 번째 열쇠**가 된다.

### DB — `0010_student_access.sql`

- `courses.entry_mode` (`code` | `approval`, 기본 `approval`)
- `student_access` — 신청·승인·이메일·마지막 입장. **학생용 RLS 정책 없음**
- `approve_all_access()` · `access_list()` · `set_access_status()` · `clear_access_email()`

### Edge Function

`student-login` 을 두 방식 모두 받도록 다시 썼다. 세션 발급 경로(진짜 Supabase
세션 + `app_metadata`)는 그대로 두고, 앞단 판정만 갈라 놓았다.

- 명단 못 맞춤 → `audit_log` 에 남기고 거절
- 여러 과목에 걸림 → 과목 목록을 돌려주고 학생이 고름
- 대기 / 거절 → 상태를 값으로 돌려줌 (예외가 아니다 — 기다리는 게 정상이다)
- 승인 + 이메일 미묶임 → 지금 묶고 입장
- 승인 + 이메일 다름 → 거절하고 `audit_log` 에 남김

### 화면

- 학생 `수업 들어가기` — 이메일·학번·이름. **승인 대기**가 오류 화면이 아니라
  하나의 결과 화면이다. 옛 수업코드 입력은 접어서 남겼다
- 교수 `수강생 → 입장 승인` — 명단 전원이 보인다(미신청 포함).
  전원 승인 · 개별 승인/거절/되돌리기 · 이메일 풀기 · 입장 방식 전환

### 주의

`0010` 은 **SQL + Edge Function 재배포 + 전원 승인** 세 가지를 다 해야 끝난다.
SQL 만 올리면 모든 과목이 승인 방식이 되는데 아무도 승인돼 있지 않아 전원이 잠긴다.
