## 2026-08-12 (밤) — 홈 화면 정리 · 반응형 자동 검사

### 탭 아이콘에 '직' 이 남아 있었다

헤더·푸터 심볼은 지웠는데 **favicon** 이 남아 있었다. 데이터 URI 안에
`%EC%A7%81` 로 인코딩돼 있어서 코드를 '직' 으로 검색해도 안 잡혔다.
브라우저 탭에서 제목 바로 앞에 붙어 보이던 게 이것이다.
글자 대신 서로 오가는 화살표 두 개로 바꿨다. 그 자리에 글자를 넣지 말 것.

### 평가 활동 = 개설 과목 6개 + 평가 2가지, 한 화면

두 섹션으로 나눠 놨던 것을 합쳤다. 같은 격자에 8장이 놓인다.
과목 카드는 링크(왼쪽 강조 줄 · '들어가기'), 평가 카드는 링크가 아니다
(회색 바탕 · 강조 줄 없음). 눈으로 구분되게 해서 헛눌러 보지 않게 한다.

### 반응형 자동 검사 — `test/responsive.check.ts`

CSS 를 글자로 읽어 규칙이 살아 있는지 본다. 브라우저를 안 띄우므로 CI 에서도 돈다.
이번에 실제로 깨졌던 두 가지를 그대로 잡는다.

- `input:not([type])` 이 선택자에서 빠지면 → 실패
- 900px 이하 `font-size: 16px !important` 가 빠지면 → 실패 (iOS 확대)

그 밖에 viewport meta, 900px 메뉴 전환(세로 ↔ select), 640px 수업 중 체크
두 줄 배치, `.table-wrap` 가로 스크롤, 집계표 첫 열 고정, 격자 auto-fill,
360px 를 넘기는 고정 폭 없음까지 20항목.

**검사를 만들고 나서 일부러 규칙을 지워 실패하는지 확인했다.**
그 과정에서 검사 자체의 결함을 찾았다 — 주석에 적힌 규칙 이름을 보고
통과하고 있었다. 주석을 먼저 걷어내도록 고쳤다.

눈으로 보는 확인을 대신하지는 못한다. 360 · 390 · 768 · 1024 · 1280 에서
직접 열어 보는 절차는 그대로다.

## 2026-08-12 (밤) — 홈 화면 정리

### 표기

- **"동료평가 학습보조 시스템" → "상호평가 학습관리시스템"**
  (`PEER ASSESSMENT SYSTEM` → `PEER ASSESSMENT LMS`)
  `brand.ts` 의 `SERVICE` 와 `index.html` 의 `<title>`·OG 태그 두 곳이다.
  `index.html` 은 React 가 뜨기 전에 읽혀서 `brand.ts` 를 못 쓴다.
- **로고 심볼 "직" 제거.** `ORG.mark` 를 빈 문자열로 두면 심볼을 안 그린다.
  **탭 아이콘(favicon)에도 '직' 이 들어 있었다** — 데이터 URI 안에
  `%EC%A7%81` 로 인코딩돼 있어서 눈으로는 안 보였다. 글자 대신 서로 오가는
  화살표 두 개로 바꿨다. 탭 제목 바로 앞에 붙는 자리라 글자를 넣으면 안 된다.
- **개인 이메일을 공개 화면에서 뺐다.** 푸터는 `CONTACT.email` 을 비웠고
  (둘 다 비면 블록째 사라진다), 헤더의 교수 이메일은 **교수 화면에서만** 보인다.

### 홈 짜임새

- 가운데 띠 → **학생 · 교수 그림 카드**. 그림 전체가 링크다.
  그림은 인라인 SVG(`components/RoleArt.tsx`) — 사진을 쓰면 학생 휴대폰
  데이터로 매번 내려받아야 하고 CDN 이 막히면 빈 칸이 된다.
- **평가 활동 한 화면에 개설 과목 6개 + 평가 2가지.**
  과목 카드는 누르면 `/login?c=<key>` 로 가고 로그인하면 그 수업으로 이어진다.
  평가 카드는 링크가 아니다(회색 · 왼쪽 강조 줄 없음).
  토론 참여 평가와 과제 동료 첨삭은 **홈에서만** 내렸다 — 시스템은 그대로 지원한다.
- 이용 안내의 학생 칸에 교수 칸과 같은 모양으로 버튼 두 개
  (들어가기 / 등록 신청). 학생은 비밀번호가 없다.

### 과목 목록은 brand.ts 에

`COURSES` 배열 하나다. `key` 는 과목 id 도 수업코드도 아닌 **힌트**라서
밖에 드러나도 아무것도 열리지 않는다. 명단에 여러 수업이 걸렸을 때 하나를
미리 골라 줄 뿐이고, 실제로 어느 수업이 열리는지는 명단과 승인이 정한다.

## 2026-08-12 (저녁) — 학생 입장 방식 교체 (수업코드 → 승인)

안내: [`50-admin-console.md` 입장 승인](50-admin-console.md#입장-승인-2026-08-12-추가) ·
적용 순서: [`11-migrate.md` 3-2](11-migrate.md)

### 왜

수업코드는 한 번 새어 나가면 막을 방법이 없다. 단톡방에 올라가면 수강생이
아닌 사람도 학번만 알면 들어온다. 학번은 같은 수업 학생끼리 서로 안다.

### 무엇으로 바꿨나

이메일 + 학번 + 이름 → **명단 대조** → **교수 승인** → 입장.
이메일은 승인 뒤의 **두 번째 열쇠**가 된다.

### DB — `0010_student_access.sql`

- `courses.entry_mode` (`code` | `approval`, 기본 `approval`)
- `student_access` — 신청·승인·이메일·마지막 입장. **학생용 RLS 정책 없음**
- `approve_all_access()` · `access_list()` · `set_access_status()` · `clear_access_email()`

### Edge Function

`student-login` 을 두 방식 모두 받도록 다시 썼다. 세션 발급 경로(진짜 Supabase
세션 + `app_metadata`)는 그대로 두고, 앞단 판정만 갈라 놓았다.

- 명단 못 맞춤 → `audit_log` 에 남기고 거절
- 여러 과목에 걸림 → 과목 목록을 돌려주고 학생이 고름
- 대기 / 거절 → 상태를 값으로 돌려줌 (예외가 아니다 — 기다리는 게 정상이다)
- 승인 + 이메일 미묶임 → 지금 묶고 입장
- 승인 + 이메일 다름 → 거절하고 `audit_log` 에 남김

### 화면

- 학생 `수업 들어가기` — 이메일·학번·이름. **승인 대기**가 오류 화면이 아니라
  하나의 결과 화면이다. 옛 수업코드 입력은 접어서 남겼다
- 교수 `수강생 → 입장 승인` — 명단 전원이 보인다(미신청 포함).
  전원 승인 · 개별 승인/거절/되돌리기 · 이메일 풀기 · 입장 방식 전환

### 주의

`0010` 은 **SQL + Edge Function 재배포 + 전원 승인** 세 가지를 다 해야 끝난다.
SQL 만 올리면 모든 과목이 승인 방식이 되는데 아무도 승인돼 있지 않아 전원이 잠긴다.
