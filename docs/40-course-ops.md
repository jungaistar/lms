# 수업 운영과 성적 산출

지금까지 이 저장소는 상호평가 하나만 다뤘다. 실제로 한 학기를 돌리려면 주차·공지·자료·과제·출석이
같은 곳에 있어야 하고, 학기 말에 그것들이 하나의 성적으로 합쳐져야 한다. 이 문서는 그 부분의 설계다.

참고한 화면은 `rest.dreamitbiz.com/admin` (AI Reboot Academy 관리자)이다. 거기서 가져온 구성은
**주차별 자료·과제 / 출결일지 / 항목별 점수표(강사 합계와 자동 합계를 나란히) / 집계표·등수표**다.

## 무엇이 생겼나

| 테이블 | 하는 일 |
|---|---|
| `course_weeks` · `course_sessions` | 주차와 회차. 출석은 주차가 아니라 **회차**에 붙는다 (주 2회 과목 때문) |
| `notices` | 과목공지 |
| `materials` | 자료실 · 학습자료실 · 강의계획서 (`kind` 로 구분) |
| `tasks` · `task_submissions` | 과제와 제출물. 과제마다 개인/팀을 따로 정한다 |
| `attendance` · `attendance_imports` | 출결과 헤이영 파일 업로드 이력 |
| `exams` · `exam_scores` | 중간 · 기말 |
| `grade_policies` | 과목별 성적 구성비 |
| `final_grades` | 합산 결과 |

`courses` 에 세 칸이 붙었다.

- `peer_assessment` — 상호평가를 하는 과목인가
- `project_mode` — `none` / `individual` / `team`
- `ext_lms_url` — 학교 LMS 주차 목록 주소 (가져오기 원본)

## 누가 무엇을 보는가

확정된 공개 정책이다. **화면에서 감추는 방식이 아니라 RLS 정책을 아예 만들지 않는 방식**으로 막는다.

| 데이터 | 교수 | 학생 |
|---|---|---|
| 주차 · 공지 · 자료 | 전부 | 공개된 것만 |
| 과제 | 전부 | 초안 아닌 것만 |
| **과제 점수 · 피드백** | 전부 | **본인 것만 공개** |
| **출결** | 전부 | **본인 것만 공개** |
| 시험 일정 | 전부 | 볼 수 있음 |
| 시험 점수 (`exam_scores`) | 전부 | **정책 없음 = 못 읽음** |
| 상호평가 원점수 (`results`) | 전부 | **정책 없음 = 못 읽음** |
| 최종 성적 (`final_grades`) | 전부 | **정책 없음 = 못 읽음** |

학생이 제출물을 고칠 수 있는 조건도 정책에 박혀 있다 — 과제가 열려 있고 **아직 채점 전**일 때만이다.
그리고 학생이 `score` / `feedback` / `graded_at` 칸에 값을 넣는 UPDATE 는 `with check` 에서 막힌다.
자기 점수를 스스로 적어 넣는 경로가 없다.

## 성적이 어떻게 나오는가

`compute_final_grades(course_id)` 하나가 유일한 계산 경로다. 클라이언트가 보낸 총점을 저장하는
길은 만들지 않는다.

```
출석 = attendance_pct × min(인정회차 / 전체회차, 1)
        인정회차: 출석 1 · 지각 late_credit(기본 0.5) · 인정결석 excused_credit(기본 1) · 결석 0
과제 = task_pct     × min(획득 / 만점합, 1)     ← 팀 과제는 팀 점수를 팀원 전원에게
중간 = midterm_pct  × min(획득 / 만점합, 1)
기말 = final_pct    × min(획득 / 만점합, 1)
상호 = peer_pct     × min(확정된 results 평균 / 100, 1)

총점 = 다섯 개의 합
```

- 구성비 합은 `grade_policies` 의 CHECK 로 **항상 100** 이 되게 강제한다.
- 결석률이 `absence_limit`(기본 0.25) 을 넘으면 총점과 무관하게 **F**.
- 아직 자료가 없는 항목(시험을 안 봤다든지)은 **만점 처리**한다. 학기 중간에 계산해도
  0점 폭탄이 뜨지 않게 하려는 것이다. 학기 말에는 반드시 자료가 다 들어와야 한다.
- 상호평가를 안 하는 과목(`peer_assessment=false`)은 `peer_pct` 를 0 으로 두고 그 몫을 다른 항목에 나눈다.
- 교수가 `status='approved'` 로 확정한 줄은 **다시 계산해도 덮어쓰지 않는다.**

등급은 95/90/85/80/75/70/65/60 경계로 A+ ~ F.

## 헤이영 출석 가져오기

헤이영에는 공개 API 가 없다. 그래서 **교수가 내려받은 파일을 올리는 방식**이다.

1. 헤이영에서 출결을 엑셀로 내려받는다.
2. 엑셀에서 `다른 이름으로 저장 → CSV UTF-8` 로 바꾼다.
   (브라우저에서 `.xlsx` 를 직접 읽으려면 라이브러리가 필요해서 일부러 CSV 만 받는다.)
3. 과목 → 출석 → 파일 올리기.

읽는 쪽은 `web/src/lib/heyyoung.ts` 다. 네트워크도 DB 도 건드리지 않는 순수 함수라
`npm test` 로 그대로 검증된다 (검사 39개).

파일 형식이 학교마다·버전마다 달라서 이렇게 처리한다.

- 머리글 이름을 못 박지 않고 **별칭 목록**으로 찾는다 (`학번`/`학생번호`/`사번`, `상태`/`출결`/`구분` …).
- 헤이영이 위에 제목·기간 줄을 얹어 주므로 **학번처럼 보이는 열이 있는 첫 줄**을 머리글로 잡는다.
- 구분자(`,` `\t` `;`)를 첫 줄에서 자동으로 고른다. BOM·CRLF·따옴표 안의 쉼표를 처리한다.
- `인정결석` 을 `결석` 보다 **먼저** 판정한다. 순서를 바꾸면 공결이 결석이 된다.
- **알아볼 수 없는 줄은 버리지 않는다.** `skipped` 에 줄 번호와 이유를 담아 돌려주고 화면에 보여 준다.
  조용히 사라지면 출석이 빠진 채로 성적이 나간다.

명단 대조(`matchRoster`)는 **학번만** 열쇠로 쓴다. 이름은 동명이인·개명 때문에 쓰지 않는다.
결과는 셋으로 나뉜다 — 맞은 행, 명단에 없는 학번, 파일에 한 번도 안 나온 학생(결석 처리 후보).

## 학교 LMS(dima) 연동

방향은 **학교 LMS 가 원본, 이쪽이 사본**이다. 주차·공지·자료·과제를 학교 LMS 에서 읽어 와 복제한다.

그래서 `course_weeks` / `notices` / `materials` / `tasks` 에 두 칸이 있다.

- `ext_ref` — 원본 쪽 식별자
- `locked` — 여기서 사람이 고친 줄. 가져오기가 덮어쓰지 않는다

`bridge/` 의 기존 원칙은 그대로다. **읽기는 HTTP, 쓰기는 브라우저 자동화 + 사람 확인**이고,
로그인 캡차는 우회하지 않는다. 학교 LMS 화면 구조를 아직 확인하지 못해
`SELECTORS_VERIFIED = false` 인 동안 자동 가져오기는 실행되지 않는다.

그동안 쓸 수 있는 길은 **주차 목록 HTML 을 저장해 올리는 것**이다. 로그인한 브라우저에서
주차 목록 페이지를 `.html` 로 저장해 올리면 같은 파서를 태울 수 있다. 이 경로는 아직 만들지 않았다.
