# 출결 · 연락처 · 문자 — 헤이영과 어떻게 붙는가

동아방송예술대학교의 출결은 **헤이영**(`campus.heyoung.co.kr`)이 원본이다.
이쪽은 사본을 들고 **수업태도 · 과제 점수를 날짜별로 얹는다.**
문자는 헤이영에서 보내되, 보낼 대상과 문안은 여기서 만든다.

관련 마이그레이션: `0012_contacts_daily_marks.sql` · `0013_messaging.sql`
관련 화면: `연락처 관리` · `일자별 기록` · `문자 · 알림`

---

## 1. 왜 이렇게 갈라 두었나

세 가지가 서로 다른 표에 들어간다. 한 표에 몰면 **학생에게 새어 나간다.**

| 무엇 | 표 | 학생이 볼 수 있나 |
|---|---|---|
| 명단 (학번 · 이름 · 팀 · 학년 · 학과) | `students` | **본다** — 팀 배분과 발표 대상에 필요 |
| 출결 | `attendance` | **본인 것만** 본다 |
| 전화번호 · 보호자 번호 | `student_contacts` | **못 본다** — 학생용 정책 없음 |
| 수업태도 · 과제 점수 (날짜별) | `session_marks` | **못 본다** — 학생용 정책 없음 |
| 문안 서식 · 보낸 기록 | `message_templates` · `message_log` | **못 본다** |

### 전화번호를 `students` 에 넣지 않은 이유

`students` 에는 `student_peer_read` 정책이 있다 (`0002_rls.sql`).
**같은 과목 학생이면 명단 전체를 읽을 수 있다.** 팀 기여도 배분과 발표 대상
표시에 이름·팀이 필요해서 그렇게 두었다.

거기에 `phone` 칸을 더하면 학생 한 명이 로그인하는 것만으로 **같은 반
30여 명의 전화번호를 통째로 가져간다.** 화면에서 감추는 방식으로는 못 막는다 —
PostgREST 에 직접 요청하면 그대로 나온다.

### 수업태도 점수를 `attendance` 에 넣지 않은 이유

`attendance` 에는 `attendance_student_read` 가 있다. 본인 출결은 본인이 본다.
거기에 점수 칸을 더하면 학생이 자기 태도 점수를 읽는다.
확정된 정책은 **점수 비공개**다.

두 표 모두 **학생용 RLS 정책을 아예 만들지 않았다.** 정책이 하나도 없는 표는
RLS 아래에서 아무 줄도 내주지 않는다. 학생 토큰으로 요청하면 빈 배열이 온다.

> 이 두 표에 학생용 정책을 추가하지 말 것. 화면에서 가리는 방식으로 바꾸지도 말 것.

## 2. 전화번호 가져오기 — `연락처 관리`

헤이영은 번호를 **마스킹해서** 보여 준다 (`010-****-5678`).
학생 이름을 눌러야 한 명씩 풀린다. 199명을 한 명씩 옮겨 적는 일을 줄이는 화면이다.

### 두 길

**① 엑셀다운 파일 올리기**

```
헤이영 → 강좌별 출석관리 → 교과목명 클릭 → 엑셀다운
→ 엑셀에서 "다른 이름으로 저장 → CSV UTF-8"
→ 연락처 관리 화면에 올린다
```

번호는 대개 마스킹된 채 들어온다. 그래도 먼저 올려 두면 **누구 번호가 비었는지**
표로 보인다. 마스킹된 줄은 `masked = true` 로만 표시하고 **번호로는 받지 않는다** —
걸 수 없는 번호를 저장해 두면 "번호가 있다" 고 착각하게 된다.

**② 마스킹 푼 줄 붙여넣기**

헤이영에서 이름을 눌러 마스킹을 해제한 뒤 그 줄을 긁어 붙여넣는다.
한 줄에 `학번 · 이름 · 전화번호` 가 있으면 된다. 머리글은 있어도 없어도 된다.

### 밟기 쉬운 자리 — DB 에서 막아 둔 것

**마스킹된 값이 이미 풀어 둔 번호를 덮지 않는다.**
엑셀다운을 두 번째로 올렸다고 애써 풀어 둔 번호가 `****` 로 돌아가면 안 된다.
`save_student_contacts()` 안에서 막는다. 화면 쪽 분기가 아니다.

**엑셀이 갉아먹은 앞자리 0 을 되살린다.**
연락처 열을 '숫자' 서식으로 저장하면 `01012345678` 이 `1012345678` 로 줄어든다.
`normalizePhone()` 이 `1[016789]` + 8자리를 보면 `0` 을 붙인다.

**학번을 번호로 읽지 않는다.**
학번은 9자리 숫자다. 구분자도 마스킹 기호도 없고 `0` 으로 시작하지도 않으면
번호로 보지 않는다.

**'보호자연락처' 가 '연락처' 를 품고 있다.**
머리글을 부분일치로만 찾으면 학생 번호 자리에 보호자 번호가 들어간다.
정확히 맞는 열을 먼저 보고, 같은 칸을 가리키면 다시 찾는다.

이 네 가지는 `web/test/contacts.check.ts` 가 지킨다 (51개 검사).

## 3. 날짜별로 적기 — `일자별 기록`

'각 일자' 는 새로 만들지 않는다. **이미 있는 회차(`course_sessions`)에 매단다.**
회차 한 줄에 `meets_on` (수업 날짜)이 붙어 있고, 출결·성적 산출이 같은 축을 본다.

> 회차가 없으면 이 화면은 비어 있다. `주/회차 관리` 에서 주차와 회차를 먼저 만들고,
> 회차에 **수업일**을 적어야 여기서 날짜로 보인다.

한 줄에 네 가지가 들어간다.

| 칸 | 저장 위치 | 되돌리기 |
|---|---|---|
| 출결 (출석·지각·결석·조퇴·인정결석) | `attendance` | 같은 버튼 다시 누르면 지워짐 |
| 수업태도 점수 | `session_marks.attitude` | 같은 점수 다시 누르면 `null` |
| 과제 점수 | `session_marks.task` | 같은 점수 다시 누르면 `null` |
| 메모 | `session_marks.note` | 비우면 `null` |

**누르면 바로 저장된다.** 저장 버튼이 없다. 언제든 다시 눌러 고칠 수 있고,
마지막으로 고친 시각이 줄 끝에 남는다.

`null` (안 매김) 과 `0` (최하점)은 다른 값이다. 이 둘을 어떻게 셀지는
`mark_policies.unmarked` 가 정한다.

| 값 | 뜻 |
|---|---|
| `skip` (기본) | 안 매긴 날은 평균에서 빼고 센다 |
| `zero` | 안 매긴 날은 0점으로 본다 (결석한 날을 깎고 싶을 때) |

만점(`attitude_max` · `task_max`)도 과목마다 정한다. 기본은 둘 다 5다.
**만점이 10 이하면 화면이 버튼을 그리고, 그보다 크면 숫자 칸으로 바뀐다** —
휴대폰에서 버튼 열 개가 넘으면 한 화면에 안 들어간다.

### 셈은 DB 가 한다

합계 · 평균 · 백분율은 화면이 세지 않는다. `session_mark_summary(p_course)`
하나가 유일한 셈 경로다. 화면과 내보내기가 모두 그 값을 그대로 옮긴다.

이 함수는 `security definer` 라 RLS 를 건너뛴다. 그래서 안에서 `owns_course()`
를 직접 부른다 — 그 한 줄이 없으면 남의 과목 id 를 넣어 부르는 것으로 명단이 샌다.

## 4. 문자 보내기 — `문자 · 알림`

### 이 시스템은 문자를 직접 쏘지 않는다

헤이영에는 공개 API 가 없다. 문자발송 화면이 어느 주소로 무엇을 POST 하는지는
로그인 상태에서 화면을 뜯어야 알 수 있고, 그건 **추측**이다.
이 저장소의 원칙은 그대로다 — 미확인 저장 엔드포인트를 추측해 호출하지 않는다.
잘못 쏘면 199명에게 잘못된 문자가 나간다.

그래서 여기까지만 한다.

1. **누구에게** — 거르기로 고른다
2. **무슨 내용** — 자리표시자를 끼워 문안을 만든다
3. **어떻게** — 헤이영이 받는 모양으로 번호를 내주거나, 기기 앱을 연다
4. **기록** — 무엇을 누구에게 보냈는지 남긴다

### ① 누구에게

| 거르기 | 쓰는 자리 |
|---|---|
| 전체 / 번호 있는 사람 / 번호 없는 사람 | 번호 채우기 독촉 |
| 고른 날짜에 결석 · 지각 · 미표시 | 그날 안 온 학생에게 바로 |
| 누적 결석이 잦은 사람 | 출석 미달 경고 (학칙상 보통 1/4) |

거른 뒤 표에서 개별로 체크를 껐다 켤 수 있다.

### ② 무슨 내용

`{이름}` `{학번}` `{과목}` `{날짜}` 를 쓸 수 있다.
`{이름}` 이나 `{학번}` 이 들어가면 **사람마다 문장이 달라져 한 통으로 못 묶는다** —
그때는 화면이 "한 명씩 보내기" 목록을 대신 낸다.

모르는 자리표시자는 **그대로 둔다.** 조용히 지우면 `{연락처}` 같은 오타가
문자에서 사라져, 교수는 잘 나간 줄 알고 이상한 문장을 보내게 된다.

바이트 수와 SMS/LMS 구분도 함께 보여 준다 (한글 2바이트, 90바이트까지 단문).

### ③ 어떻게

**헤이영으로** — 번호 목록을 세 가지 모양으로 내준다.
헤이영 문자발송 화면이 받는 모양이 저마다 달라서 하나로 고정하지 않았다.

| 모양 | 결과 |
|---|---|
| 한 줄에 하나 | `010-1111-1111`⏎`010-2222-2222` |
| 쉼표로 이어서 | `010-1111-1111, 010-2222-2222` |
| 하이픈 없이 | `01011111111`⏎`01022222222` |

복사 → 헤이영 문자발송 화면에 붙여넣기 → 보내기는 교수가 누른다.

**기기로** — `sms:` `mailto:` 는 브라우저 표준이라 아이폰 · 안드로이드 폰 ·
아이패드 · 안드로이드 태블릿 · 맥북에서 각자의 기본 앱이 열린다.

> **iOS 와 안드로이드는 `sms:` 문법이 반대다.**
> iOS 는 `sms:번호&body=…`, 안드로이드는 `sms:번호?body=…` 다.
> 틀리면 본문이 통째로 사라진다. `isAppleDevice()` 가 이걸 가른다 —
> 요즘 아이패드 사파리는 자기를 맥이라고 말해서 터치 지원까지 함께 본다.

**메일** — 받는 사람은 **전부 숨은참조(BCC)** 다.
참조로 넣으면 학생 199명이 서로의 이메일 주소를 보게 된다.
`web/test/messaging.check.ts` 가 `to=` · `cc=` 로 새지 않는지 검사한다.

노트북에서 지메일을 브라우저로 쓰는 경우를 위해 **구글 메일 작성 창** 링크도 낸다.

**카카오톡** — 자동 발송은 **안 된다.** 사업자 채널과 알림톡 서식 승인이 있어야
하고, 그건 이 저장소가 대신할 수 있는 일이 아니다.
대신 기기 **공유 시트**(`navigator.share`)를 연다 — 거기 뜨는 카카오톡을 골라 보낸다.

### ④ 기록

`message_log` 에 남는다. 다만 **이쪽이 대행한 게 아니라 교수가 눌러 남긴 표시**다 —
통신사 전송 결과가 아니다. "그 학생한테 연락했던가?" 를 나중에 확인하려고 둔다.

받는 사람 목록에 **전화번호는 담지 않는다.** 기록에 번호를 복제해 두면
나중에 지울 자리가 하나 더 늘어난다.

### 헤이영 푸시 (2026-08-23 확인 · 추가)

**헤이영 교수 메뉴에는 문자발송 화면이 없다.** 그날 교수 계정(C62005)으로 직접
열어 보고 알았다. `UMS시스템` 아래에 있는 것은 푸시뿐이다.

```
UMS시스템 → 푸시 → 푸시 전송 · 컨텐츠관리 · 전송결과 · 전송통계
```

그리고 예전에 코드에 적어 둔 문자발송 주소 `/admin/screen/HCO0301M01` 은
**404 였다** — 화면 경로에 `/admin` 이 없다. 확인한 주소는 이렇다.

| 화면 | 주소 |
|---|---|
| 푸시 전송 | `campus.heyoung.co.kr/screen/HMS0201M02` |
| 푸시 수신자 추가 | `.../screen/HMS0201M04` |
| 전송결과 | `.../screen/HMS0203M01` |
| 전송통계 | `.../screen/HMS0204M01` |
| 컨텐츠관리 | `.../screen/HMS0205M01` |

#### 푸시 전송 화면이 요구하는 것

제목 · 내용 · 이미지(JPG/JPEG, 선택) · 예약전송 체크 · **수신자 목록**.
알림 종류는 `헤이영 / 학교알림 / 포털알림 / 학과알림` 중에서 고른다.

**수신자는 번호가 아니라 학번으로 찾는다.** 그래서 이쪽 화면은 문자와 달리
번호가 아니라 **학번 목록**을 내준다 (`pushRecipientList()`).

수신자 추가는 두 길이다.

1. **강좌 단위** — 년도학기와 강좌를 고르고 검색하면 그 강좌 학생이 한 번에
   나온다. 전체 체크 후 `선택추가`. 반 전체에 보낼 때는 이 길이 빠르다.
2. **한 명씩** — `이름 및 학번/교번` 칸은 한 명만 받는다. 결석자처럼 일부에게만
   보낼 때 우리 화면이 낸 학번 목록을 하나씩 넣는다.

#### 문자와 갈리는 자리

**번호가 없는 학생도 목록에서 빼지 않는다.** 푸시는 번호를 쓰지 않기 때문이다.
빼 버리면 앱은 깔았는데 번호만 아직 안 적어 낸 학생이 조용히 사라진다.
문자 쪽 `phoneList()` 는 반대로 번호 없는 사람을 뺀다 — 걸 데가 없어서다.

대신 푸시에는 다른 구멍이 있다. 화면이 이렇게 적어 두었다.

> 푸시메세지는 헤이영캠퍼스 앱이 설치자인 경우에만 수신가능합니다.

**앱을 깔지 않은 학생에게는 가지 않는다.** 그리고 이쪽은 누가 앱을 깔았는지
알 길이 없다. 그래서 중요한 공지는 푸시 하나만 믿으면 안 된다.

#### 여전히 이쪽이 쏘지 않는다

`0013` 때와 같다. 헤이영에는 공개 API 가 없고, 전송 화면이 어느 주소로 무엇을
POST 하는지는 화면을 뜯어야 알 수 있는 **추측**이다. 잘못 쏘면 한 번에 수십 명에게
잘못된 알림이 간다. 그래서 **제목 · 내용 · 학번 목록까지만** 만들고
`메시지전송` 은 교수가 헤이영에서 누른다.

`message_log` 에는 `heyyoung_push` 로 남는다 (`0014_push_channel.sql` 이
채널 목록을 넓힌다). 통신사 전송 결과가 아니라 **교수가 어느 버튼을 눌렀는지**다 —
실제 도달은 헤이영 `전송결과` 화면에서 본다.

## 5. 기기 — 어디까지 확인했나

학생은 아이폰 · 안드로이드 폰 · 아이패드 · 안드로이드 태블릿 · 맥북 아무거나 들고 온다.
교수도 수업 중에는 태블릿으로 본다. 세 단계로 접힌다.

| 폭 | 일자별 기록 한 줄이 어떻게 되나 |
|---|---|
| ~640px | 묶음(출결 · 태도 · 과제 · 메모)마다 한 줄. 버튼이 줄을 고르게 나눠 갖는다 |
| ~900px | 묶음 두 개가 한 줄에. 사이에 1px 선을 둔다 |
| 901px~ | 묶음이 내용 폭대로 서고, 메모가 남는 폭을 먹는다 |

**묶음 사이의 1px 선이 왜 있나** — 없으면 수업태도 `0~5` 와 과제 `0~5` 가 붙어
**똑같이 생긴 버튼 열두 개** 한 줄로 보인다. 라벨은 위에 있어서 누를 때는 눈에
안 들어온다. 태블릿에서 실제로 옆 묶음을 누르게 된다.

**터치 대상 44px** — `.btn-sm` 의 기본은 40px 이다. 900px 이하에서는 버튼도
44px 로 올린다. 수업 중에 서서 누를 때 40px 로는 옆 칸이 눌린다 —
출결을 잘못 찍으면 성적이 틀어진다.

### 눈으로 확인하는 법

교수 화면은 로그인해야 열린다. 레이아웃만 따로 보려면:

```bash
cd web && npm run build && npm run responsive
npm run preview   # → http://localhost:4173/responsive-check/
```

한 줄의 레이아웃만 빠르게 보려면 `web/tools/mark-row-preview.html` 을 연다.
실제 `styles.css` 를 그대로 물리고, 마크업은 `DailyTab.tsx` 가 그리는 것과 같다.

`npm test` 의 `responsive.check.ts` 는 위 규칙이 CSS 에 살아 있는지만 읽는다.
브라우저를 안 띄우므로 **눈으로 보는 확인을 대신하지 못한다.**

## 6. 적용 순서

```
Supabase SQL Editor 에서
  0012_contacts_daily_marks.sql
  0013_messaging.sql
```

둘 다 끝에 `notify pgrst, 'reload schema'` 가 있다. 이걸 빼먹으면 SQL 은
분명히 올라갔는데 앱에서는 `Could not find the table … in the schema cache` 가 계속 난다.
