# 03. 아키텍처 제안

## 3.1 한 문장 요약

> **읽기는 HTTP 클라이언트로, 판단은 AI 초안으로, 쓰기는 사람 확인 후 브라우저 자동화로.**

REST API가 없는 시스템에서 안전하게 자동화하는 유일한 현실적 경로입니다.

## 3.2 전체 흐름

```
 ┌─ 사람 ──────────────┐
 │ 브라우저에서 로그인   │   ← 캡차 때문에 자동화 불가. 이 단계는 항상 사람.
 │ (슬라이더 캡차 통과)  │
 └──────────┬───────────┘
            │ 세션 쿠키 저장 (.auth/state.json, git 제외)
            ▼
 ┌─ 수집 (읽기 전용) ────────────────────────────────┐
 │ doListView / doMarkView / doFormReportMark …      │
 │ HTML 파싱 → 정규화                                 │
 └──────────┬────────────────────────────────────────┘
            ▼
 ┌─ 로컬 SQLite ────────────────────────────────────┐
 │ courses · students · reports · submissions        │
 │ 원본 스냅샷 보존 (raw_html 포함)                    │
 └──────────┬────────────────────────────────────────┘
            ▼
 ┌─ 채점 초안 생성 ──────────────────────────────────┐
 │ 루브릭 + 제출물 → Claude → {점수, 근거, 피드백}     │
 │ 상태: draft                                        │
 └──────────┬────────────────────────────────────────┘
            ▼
 ┌─ 사람 검토 ───────────────────────────────────────┐
 │ 초안 확인·수정 → 상태: approved                     │
 │ **검토되지 않은 초안은 절대 다음 단계로 못 감**       │
 └──────────┬────────────────────────────────────────┘
            ▼
 ┌─ 제출 (쓰기) ─────────────────────────────────────┐
 │ Playwright로 실제 채점 화면 열기                    │
 │ 입력창 채움 → 화면 캡처 → **학생 단위 확인** → 저장   │
 │ 저장 후 값 재조회하여 검증                           │
 └───────────────────────────────────────────────────┘
```

## 3.3 왜 쓰기를 직접 호출하지 않는가

두 가지 이유입니다.

**(a) 데이터 손상 위험.**
저장 API의 정확한 파라미터와 서버측 검증 로직을 100% 파악하지 못했습니다.
필수 파라미터 하나를 빠뜨리거나 잘못된 형식으로 보내면
성적이 0으로 덮이거나, 다른 회차에 기록되거나, 부분 저장으로 정합성이 깨질 수 있습니다.
**성적은 되돌리기 어려운 데이터입니다.**

**(b) 기관 정책.**
학교 IT 정책상 비공식 API 호출이 허용되지 않을 수 있습니다.
브라우저에서 사람이 하는 것과 동일한 조작은 정책적으로도 훨씬 방어 가능합니다.

브라우저 자동화는 느립니다. 하지만 **성적 데이터에서는 느린 게 맞습니다.**

## 3.4 계층 설계

| 계층 | 책임 | 이 계층이 절대 하지 않는 것 |
|---|---|---|
| `src/lms/session.ts` | 세션 쿠키 확보·저장·생존 확인 | 로그인 자동 시도 |
| `src/lms/client.ts` | 쿠키 실어 HTTP 요청, 레이트리밋, 세션 만료 감지 | **쓰기 요청 전송** |
| `src/lms/parse.ts` | HTML/JSON 응답 → 정규화된 객체 | 네트워크 호출 |
| `src/collect/*` | 화면별 수집 로직 | 데이터 가공·판단 |
| `src/db/*` | 로컬 저장, 원본 스냅샷 보존 | 외부 통신 |
| `src/grade/*` | 루브릭 적용, 초안 생성 | LMS 접근 |
| `src/automation/*` | 브라우저로 점수 입력 | 사람 확인 없이 저장 |

핵심: **`client.ts`는 GET/POST 조회만 가능하도록 코드 수준에서 막습니다.**
쓰기 경로는 오직 `automation/`에만 존재합니다. 실수로 섞일 수 없게 물리적으로 분리합니다.

## 3.5 안전장치 (하나라도 빼지 말 것)

| 장치 | 동작 |
|---|---|
| `DRY_RUN=true` 기본값 | 어떤 저장도 실제로 수행되지 않음. 명시적으로 꺼야 함 |
| 학생 단위 확인 | 저장 직전 화면 캡처 + 값 표시 → 사람이 승인해야 다음으로 |
| 승인 상태 검사 | `approved`가 아닌 초안은 제출 단계 진입 불가 |
| 저장 후 검증 | 저장 뒤 값을 다시 읽어 의도한 점수와 일치하는지 확인 |
| 원본 스냅샷 | 손대기 전 점수를 `submissions.original_score`에 보존 |
| 감사 로그 | 모든 쓰기 시도를 시각·학생·이전값·새값과 함께 기록 |
| 레이트리밋 | 요청 간 1.2초 이상. 학교 서버 부담 방지 |

## 3.6 학기 전환

`course_id`, `class_no`만 새 학기 값으로 교체하면 동일 로직이 재사용됩니다.
따라서 **어떤 식별자도 코드에 하드코딩하지 않습니다.** 전부 `.env` 또는 CLI 인자로 주입합니다.

```bash
# 1학기
npm run collect -- --course 202610UN0060****Y2 --class Y2
# 2학기 — 코드 변경 없음
npm run collect -- --course 202620UN0060****Y2 --class Y2
```
