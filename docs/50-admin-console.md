# 관리자 콘솔 — 왼쪽 메뉴 · 학교 LMS 과제 연동 · 설문

2026-08-12 작업. 이전 문서는 [`40-course-ops.md`](40-course-ops.md) 에 있다.

## 왜 바꿨나

과목 화면이 가로 탭 아홉 개였다. 화면이 열여덟 개로 늘면서 탭이 화면 밖으로
밀려 지금 어디에 있는지 알 수 없게 됐다. 그래서 **왼쪽 세로 메뉴**로 바꿨다.

짜임새는 두 곳을 로그인 상태로 직접 보고 옮겼다. 추측이 아니다.

| 참고한 곳 | 무엇을 가져왔나 |
|---|---|
| `rest.dreamitbiz.com/admin/*` | 왼쪽 "관리자 메뉴" 의 짜임새 — 제목 · 그룹 · 선택 항목 강조 · 맨 아래 "사이트로 돌아가기" |
| `lms.dima.ac.kr` 강의실 왼쪽 메뉴 | 항목 이름 — 강의홈 · 주/회차 관리 · 과목공지 · 학습자료실 · 과제관리 · 설문등록/결과조회 |

## 메뉴 짜임새

```
관리자 메뉴
├ 현황       대시보드
├ 수강생     수강생 관리 · 명단 대조 · 팀 편성
├ 수업 운영  주/회차 관리 · 과목 공지 · 자료 관리 · 과제 관리 ·
│            과제 제출현황 · 설문 등록·결과
├ 출결·기타  출석 관리 · 수업 중 체크 · 기타·감점
├ 상호평가   루브릭 · 평가 활동          (상호평가 쓰는 과목만)
├ 프로젝트   사전평가 집계표 · 결과평가 집계표  (프로젝트 있는 과목만)
├ 성적       학습평가 성적
└            내 과목 목록 · 사이트로 돌아가기
```

과목 설정(`peer_assessment`, `project_mode`)에 따라 그룹이 빠진다.
**감춰도 권한은 RLS 가 판단한다** — `web/src/teacher/adminMenu.ts` 를 고쳐도
남의 과목은 열리지 않는다.

지금 메뉴는 주소에 남는다: `#/teacher/course/<id>?m=attendance`.
새로고침해도 보던 화면이 열리고, 특정 화면 링크를 그대로 붙여 쓸 수 있다.

## 기기 폭에 따라 달라지는 것

학생은 아이폰·안드로이드·태블릿·노트북 아무거나 들고 오고, 교수도 수업 중에는
태블릿으로 본다. **360px 부터 1440px 까지 한 화면으로 다 돌아야 한다.**

| 폭 | 관리자 메뉴 | 그 밖에 |
|---|---|---|
| 360 ~ 640 | 네이티브 select | 수업 중 체크가 한 학생 두 줄 · 출결 버튼 5개가 한 줄에 고르게 |
| 641 ~ 900 | 네이티브 select | 입력 글자 16px 강제 · 터치 대상 44px |
| 901 ~ | 왼쪽 세로 메뉴 (232px) | 본문과 나란히 |

### 왜 좁은 화면은 select 인가

처음에는 세로 메뉴를 그대로 눕혀 **가로로 밀리는 띠**로 만들었다.
390px 에서 실제로 열어 보니 18개 중 **3개만 보이고 그룹 이름도 사라졌다.**
"학습평가 성적" 하나 찾으려면 한참을 문질러야 했다. 수업 중에 쓸 물건이 아니다.

네이티브 `<select>` 는 iOS·안드로이드가 각자 자기 피커를 띄운다 —
한 번 눌러 18개를 다 보고, `optgroup` 으로 그룹 이름도 남는다.

메뉴 정의는 `adminMenu.ts` 한 배열이다. 두 모양이 같은 배열을 읽으므로 어긋나지 않는다.

### iOS 확대 문제

사파리는 **16px 미만** 입력에 포커스가 가면 화면을 확대한다. 한 번 확대되면
되돌아오지 않아서 그 뒤로 계속 옆으로 밀린 화면을 보게 된다.
화면 코드 곳곳에 `fontSize: 14` 가 인라인으로 박혀 있어서
`@media (max-width: 900px)` 에서 `!important` 로 되돌린다.
인라인을 하나씩 지우면 다음에 또 생긴다 — 한 곳에서 막는다.

### 확인하는 법

```bash
cd web && npm run build && npm run responsive
npm run preview          # 다른 터미널에서
# http://localhost:4173/lms/responsive-check/
```

앱을 **고정 폭 iframe** 에 띄운다. iframe 폭이 곧 CSS 뷰포트라 미디어 쿼리가
그대로 걸리고, 같은 출처라 로그인 세션도 이어진다.
브라우저 창을 줄여 보는 것으로는 안 된다 — 창을 줄여도 뷰포트가 안 따라오는
경우가 있다(이번에 실제로 그랬다).

## 새로 생긴 화면

### 대시보드
`course_overview()` 한 번으로 숫자를 전부 받는다. 표를 열 개 따로 세면
요청이 열 번 나가고 그중 하나만 실패해도 화면이 반쪽이 된다.
아래 "지금 할 일" 은 비어 있는 곳을 짚어 준다.

### 명단 대조
학교 LMS 명단을 붙여넣고 이쪽 명단과 비교한다. **학번만** 열쇠로 쓴다.

- 학교 LMS 에만 있음 → 눌러서 명단에 넣는다
- 이 사이트에만 있음 → 눌러서 **제외**한다 (지우지 않는다 — 평가·출결이 딸려 사라진다)
- 학번은 같은데 이름이 다름 → 눌러서 학교 LMS 쪽으로 맞춘다

### 팀 편성
팀 단위로 보는 자리다. 인원이 몰린 팀, 팀 없는 학생, 팀 이름 바꾸기.
자동 배정은 **섞은 뒤 라운드로빈**으로 돌려 담는다. 학번 순으로 자르면
같은 과·같은 학년이 한 팀에 몰린다.

### 수업 중 체크
출석 화면과 따로 있는 이유 — 출석 화면은 수업이 끝난 뒤 헤이영 파일을 올려
정리하는 자리고, 이 화면은 **수업 도중에 서서 누르는** 자리다.

- 오늘 날짜에 걸린 회차를 알아서 고른다
- 이름·학번으로 걸러 찾는다
- 한 번 누르면 그 자리에서 저장된다 (저장 버튼이 없다)
- 같은 버튼을 다시 누르면 표시가 지워진다

헤이영은 지문·QR 로 **출석**만 찍는다. 늦게 들어온 학생도 출석으로 남는다.
여기서 **지각**을 누르면 그 칸이 `source = manual` 로 덮인다. 덮었다는 표시가
남으므로 나중에 헤이영 파일을 다시 올려도 무엇을 고쳤는지 알 수 있다.

**태도 불량**은 세어 줄 근거가 없다. `−` `+` 로 누른 만큼만 쌓인다.

### 설문 등록 · 결과
학교 LMS 강의실의 "설문등록/결과조회" 자리다. 문항은 세 가지 —
점수(1~N) · 보기 중 하나 · 서술.

**익명이 기본이다.** 익명일 때 교수는 *누가 냈는지*만 보고 *무엇을 썼는지*는
합계로만 본다. 화면에서 가리는 게 아니라 `survey_answers` 에 교수용 RLS 정책이
**아예 없어서** 못 읽는다. 집계 함수 `survey_summary()` 만 통과한다.
서술형 원문은 집계 함수가 순서를 섞어 돌려준다 — 제출 순서로 사람을 짚지
못하게 하려는 것이다.

학생은 한 번만 낼 수 있다. 익명 설문에서 수정을 열어 두면 "누가 뭘 고쳤나" 를
되짚을 수 있어야 하고, 그 순간 익명이 아니게 된다.

### 프로젝트 사전평가 · 결과평가 집계표
같은 루브릭으로 학기 초(사전)와 학기 말(결과)을 두 번 평가하고,
그 결과를 **대상 × 항목** 표로 눕힌다.

어느 활동이 사전이고 어느 활동이 결과인지는 **사람이 정한다** —
활동에 붙인 `activities.phase` 하나로 갈린다. 제목으로 짐작하지 않는다.
평균과 등수는 `project_eval_summary()` · `project_eval_totals()` 가 만든다.
화면에서 다시 더하지 않는다.

## 과제 제출현황 — 학교 LMS 에서 가져오기

**학교 LMS 가 원본이다.** 학생은 거기에 과제를 낸다. 이쪽은 그 결과를 받아
기타 점수(감점)로 바꾼다.

학교 LMS 과제 화면은 두 모양으로 나온다. 주는 정보가 달라서 반영하는 곳도 다르다.

### ① 학생별 과제 (제출수)

`과제관리 → 학생별 과제` 표. 이렇게 생겼다.

```
NO  학교명  학년  학번        이름   핸드폰  제출수  조회
1   학부    3    202126002   고재욱          3/3     조회
2   학부    3    202415002   고채연          2/3     조회
```

줄에서 **학번**과 **제출수(n/N)** 만 찾는다. 열 순서는 상관없다.
못 낸 개수가 `학교 LMS 과제 미제출` 감점 항목의 건수가 된다.

- 과제를 이 사이트에 등록하지 않아도 된다
- 대신 **어느 과제인지도, 늦었는지도 모른다**
- 붙여넣은 학생만 덮어쓴다. 안 나온 학생은 손대지 않는다 —
  표를 일부만 긁어 왔을 때 나머지가 0 이 되면 안 된다

### ② 과제별 제출 목록

`과제관리(출제/채점) → 채점하기` 목록. 과제 하나에 대해 누가 언제 냈는지 준다.

```
202126002   고재욱   2026-03-16 21:04
202415002   고채연   2026-03-17 09:12
202439003   권시온   미제출
```

이 사이트에 같은 과제를 만들어 두고 고른 뒤 붙여넣는다.
마감시각과 비교해 **지각 제출**을 스스로 가른다.
붙여넣기에 상태 낱말("지각", "미제출")이 있으면 **그쪽을 먼저 믿는다** —
학교 LMS 가 자기 규칙으로 이미 판정한 것이라 우리가 마감시각을 잘못 넣었을
때보다 정확하다.

"붙여넣기에 안 나온 학생을 미제출로 표시" 는 **표를 다 긁어 왔을 때만** 켠다.

### 두 방식을 겹쳐 쓰면 두 번 깎인다

①은 감점 항목(`ext_task_missing`)에 건수를 넣고, ②는 `task_submissions` 에
상태를 넣어 자동 집계(`task_missing` · `task_late`)를 움직인다.
같은 과제를 양쪽에 넣으면 감점이 두 번 붙는다.

화면이 이 상황을 감지해 경고한다. 하나를 고르면 된다.

- ① 만 쓸 거라면 → 이 사이트의 과제를 **준비중**으로 두거나,
  `기타 · 감점`에서 `과제 미제출` 항목을 0 점으로 둔다
- ② 만 쓸 거라면 → `학교 LMS 과제 미제출` 항목을 0 점으로 둔다

### 기말에 한 번에 처리하기

학기 중에는 아무 때나 다시 가져오면 된다. **덮어쓰기라서 여러 번 해도 된다.**
기말에는 이 순서로 한다.

1. `과제 제출현황` → 마지막으로 한 번 더 가져온다
2. `기타 · 감점` → 항목별 점수를 확인한다
3. `학습평가 성적` → **성적 산출**을 누른다

성적은 `compute_final_grades()` 하나가 만든다.
기타 점수 = `etc_pct × max(etc_base − 감점합, 0) / etc_base`.

## 기타 점수에 들어가는 것

`seed_deduction_kinds()` 가 깔아 주는 기본 항목이다.

| 항목 | 어디서 세나 | 기본 점수 |
|---|---|---|
| 지각 | 출결 `late` | 1 |
| 조퇴 | 출결 `early_leave` | 1 |
| **결석** | 출결 `absent` | **0** |
| 태도 불량 | 사람이 직접 (수업 중 체크) | 2 |
| 과제 미제출 | 이 사이트 과제 | 5 |
| 과제 지각 제출 | 이 사이트 과제 | 2 |
| 학교 LMS 과제 미제출 | ① 가져오기 (필요할 때 생김) | 과제 미제출과 같게 |

**결석이 0 점인 이유** — 결석은 출석 점수에서 이미 깎인다. 항목만 열어 두고
점수는 0 으로 둬서 이중 감점을 막았다. 기타에서도 세고 싶으면 점수를 올린다.

## 학생 화면

| 주소 | 화면 | 무엇이 보이나 |
|---|---|---|
| `/home` | **강의홈** (새로 만듦) | 고정 공지 · 이번 주 수업 · 해야 할 것(과제·설문·상호평가) · 내 출결 요약 |
| `/lessons` | 주차 학습 | 주차별 공지 · 자료 · 과제 |
| `/me` | 내 평가 | 해야 할 상호평가 |
| `/survey/:id` | **설문 참여** (새로 만듦) | 척도는 버튼으로 고른다. 한 번만 낼 수 있다 |
| `/record` | 내 기록 | 본인 출결 · 과제 점수 · 감점 |
| `/feedback` | 받은 피드백 | 익명 코멘트 |

로그인하면 `/home` 으로 간다. 화면 위 줄(`StudentNav`)로 오간다.

**점수 공개 정책은 그대로다.** 과제 점수와 출결은 본인 것만,
상호평가 원점수·시험 점수·최종 성적은 학생에게 내려가지 않는다.
