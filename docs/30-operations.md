# 30. 학기 중 운영

실제로 수업에서 어떤 순서로 쓰는지입니다.

---

## 학기 시작 (한 번)

1. **과목 만들기** — 학기·과목명·분반, 수업코드 자동 생성
2. **명단 붙여넣기** — 학교 LMS 명단에서 `학번 · 이름 · 팀` 순서로 긁어서 붙여넣기
   (팀은 나중에 표에서 바꿔도 됩니다)
3. **루브릭 만들기** — 견본으로 시작해서 항목을 고칩니다

> 루브릭 항목의 만점은 **5점을 넘기지 마세요.** 10점·100점 척도를 주면
> 대부분 "잘했으면 90, 못했으면 70"으로 뭉개져 변별이 안 됩니다.
> 0~5로 좁히고 항목 수를 늘리는 쪽이 훨씬 잘 갈립니다.

---

## 발표 수업 당일

| 시점 | 할 일 |
|---|---|
| 수업 전날 | 활동 만들기 → `팀 목록으로 대상 만들기` → `배정 생성` |
| 발표 직전 | `열기` 누르고 **수업코드를 칠판에 씁니다** |
| 발표 중 | 학생들이 휴대폰으로 평가 입력. 교수 화면에서 제출 현황이 실시간으로 보입니다 |
| 발표 직후 | `마감` → `집계하기` |
| 나중에 | 결과 검토 → 필요하면 덮어쓰기 → `확정` |

**팁**: 발표가 끝날 때마다 마감하지 말고, 수업 전체가 끝난 뒤 한 번에 마감하세요.
발표 순서가 뒤인 조가 불리해지지 않습니다.

**대상당 평가자 수**는 5명 이상을 권합니다. 3명 이하면 한 사람의 편차가 그대로 점수가 됩니다.
학생 30명 / 6개 조 수업이면 `evaluators_per_target = 8` 정도가 적당합니다
(학생 1인당 평가 부담도 8건 정도로 맞춰집니다).

---

## 토론 수업

1. 활동 종류를 **토론 참여 평가**로 만들고 `열기`
2. 학생들이 토론방에 글·답글을 씁니다 (토론은 **실명**입니다 — 익명이면 대화가 안 됩니다)
3. 토론이 끝나면 `학생 목록으로 대상 만들기` → `배정 생성`
4. 학생들이 서로의 참여를 루브릭으로 평가 (이때 **코멘트는 익명**)
5. `마감` → `집계하기` → `확정`

---

## 팀 프로젝트 마무리

1. 명단에 **팀이 지정돼 있어야 합니다** (안 되어 있으면 학생 화면에 안내가 뜹니다)
2. 활동 종류를 **팀 기여도 평가**로 만들고 `열기`
   - 평가 대상·배정 단계가 없습니다. 팀원끼리만 서로 배분하므로 자동입니다
3. 학생들이 팀원에게 100점을 배분 (합계가 정확히 100이어야 제출됩니다)
4. `마감` → `집계하기`
5. 결과에서 `factor` 가 낮은 학생을 확인하고, 필요하면 면담 후 `덮어쓰기`

---

## 과제 동료 첨삭

1. 활동 종류를 **과제 동료 첨삭**, 평가 대상을 **개인**으로 만듭니다
2. `학생 목록으로 대상 만들기` 후, 각 대상의 `content` 에 과제 본문이나 링크를 넣습니다
   (현재는 DB에서 직접 넣거나, 학교 LMS에서 수집한 것을 붙여넣습니다 —
   `bridge/` 의 수집 기능을 씁니다)
3. `배정 생성` → `열기`
4. 이후는 발표와 같습니다

---

## 성적을 학교 LMS로 넘기기

1. 활동 화면에서 **CSV 내려받기**
2. CSV 컬럼: `학번, 이름, 원점수(100), 보정점수(100), 평가참여율, 평가자수, 최종(N점)`
3. 학교 LMS 성적산출 화면을 열고 **최종 열의 값을 입력**합니다

```bash
cd bridge
npm run auth                                        # 사람이 직접 로그인 (캡차)
npm run push -- --csv "3주차 발표_성적.csv" --dry-run
```

> ⚠️ 현재 `bridge/` 의 성적 입력은 **잠겨 있습니다** (`SELECTORS_VERIFIED = false`).
> 성적산출 화면의 입력 마크업을 아직 확인하지 못했기 때문입니다.
> 그 전까지는 CSV를 보고 화면에서 직접 입력하세요 — 30명이면 5분입니다.
> 잘못된 칸에 성적이 들어가는 것보다 낫습니다.
>
> 학교 LMS 연동의 배경과 원칙은 [bridge/](bridge/03-architecture.md) 문서를 보세요.

## 다음 학기

과목만 새로 만들면 됩니다. 루브릭은 새 과목에서 다시 만들어야 하지만,
견본에서 시작하면 몇 분입니다.
학교 LMS 연동 식별자(`course_id`, `class_no`)만 새 학기 값으로 바꿉니다.

---

## 자주 겪는 상황

| 상황 | 대응 |
|---|---|
| 학생이 결석해서 평가를 못 했다 | 명단에서 `제외` 처리하면 배정과 집계에서 빠집니다 |
| 학생이 중간에 들어왔다 | 명단에 추가 후 `배정 생성` 을 다시 누릅니다 (기존 배정은 유지됩니다) |
| 팀이 바뀌었다 | 명단 표에서 팀을 바꾸고 재집계 |
| 한 조가 평가를 3건밖에 못 받았다 | 화면에 경고가 뜹니다. 마감을 미루거나, 해당 조만 교수 평가로 대체 |
| 누가 봐도 이상한 점수가 있다 | 결과 표에서 `덮어쓰기` 로 조정. 확정 전이면 언제든 가능 |
| 이미 확정했는데 고쳐야 한다 | Supabase 대시보드에서 해당 `results` 행의 `status` 를 `draft` 로 되돌립니다 |
