## 2. 원본 접근 문제 — 가장 먼저 걸린 것

작업을 시작하자마자 원본을 받을 수 없다는 것이 확인됐다.

```
$ curl -sS https://nonghyupsaryo.dreamitbiz.com/
curl: (56) CONNECT tunnel failed, response 403
```

```
$ curl -sS "$HTTPS_PROXY/__agentproxy/status"
"recentRelayFailures": [{
  "kind": "connect_rejected",
  "detail": "gateway answered 403 to CONNECT (policy denial or upstream failure)",
  "host": "nonghyupsaryo.dreamitbiz.com:443"
}]
```

작업 환경의 **네트워크 정책이 이 도메인을 막고 있다.** `example.com` 같은 다른
주소도 똑같이 막혀 있으니 이 사이트만의 문제는 아니고, 환경이 원래 그렇다.
검색 도구만 열려 있어 회사 정보 정도는 확인할 수 있었지만,
**화면 자체(HTML · CSS · 이미지)는 한 바이트도 받지 못했다.**

덧붙여 원본 주소가 `/#/` 로 끝나는 것을 보면 **해시 라우팅 SPA** 다.
설령 접근이 됐더라도 첫 응답 HTML 에는 빈 껍데기만 있고 내용은 JS 가 그린다 —
"HTML 을 받아 그대로 저장"하는 방식으로는 어차피 복제가 안 되는 구조다.

### 그래서 어떻게 했나

원본의 문구 · 이미지 · 데이터를 그대로 가져오는 대신,
**한국 기업 사이트가 공통으로 쓰는 화면 구성과 상호작용을 직접 구현했다.**
화면에 나오는 모든 글과 숫자는 이 실습을 위해 새로 지어낸 것이다.

| 가져온 것 | 지어낸 것 |
|---|---|
| 화면 짜임새 (상단 유틸바 → 로고 · GNB → 히어로 → 퀵메뉴 → 게시판 → 푸터) | 회사 소개 문구, 인사말 |
| 서브 페이지 관용구 (breadcrumb + 페이지 제목 + 좌측 세로 메뉴) | 제품 18종의 이름 · 성분 수치 |
| 기업형 게시판 관용구 (번호 · 분류 · 제목 · 등록일 · 조회) | 게시글 18건 |
| 축산 사료 업종에서 다루는 정보 종류 (축종 · 급여 구간 · 조단백 · TDN) | FAQ 6건, 대리점 11곳, 연혁 |

실습 목적에는 이쪽이 오히려 낫다. 학생이 만들 화면의 **패턴**이 중요하지
남의 회사 소개글이 필요한 게 아니기 때문이다. 다만 오해를 막기 위해
**푸터와 각 섹션 하단에 "실습본이며 실제 정보가 아니다"라고 명시**해 두었다.

### 원본을 반영하고 싶다면

강의실 PC 에서는 원본 사이트가 열릴 것이다. 그렇다면 이 실습본을 뼈대로 두고
다음 순서로 맞춰 가면 된다.

1. 브라우저에서 원본을 열고 `Ctrl+S` → **웹페이지 전체** 로 저장
2. 개발자 도구 `Network` 탭에서 SPA 가 부르는 **JSON 응답**을 확인
   (게시판 · 제품 목록은 대개 여기 있다)
3. 이 실습본의 `_build/pages/*.html` 안 **데이터 배열**(`PRODUCTS`, `POSTS`)만 갈아 끼운다
   — 화면 코드는 손댈 필요가 없다. 배열이 화면을 만들도록 짜 두었다
4. 색은 `_build/parts/style.css` 맨 위 `:root` 변수만 고친다

## 3. `D:\data\dev\` 문제

이 작업은 **원격 리눅스 컨테이너**에서 돌아간다. 사용자 PC 의 `D:` 드라이브에
직접 파일을 쓸 방법이 없다.

그래서 저장소에 만들어 두고, **그 경로로 옮기는 스크립트를 같이 넣었다.**

- `농협/setup-local.ps1` — PowerShell
- `농협/setup-local.bat` — 더블클릭용

둘 다 `D:\data\dev\농협` 에 자료를 놓고, 없으면 폴더를 만들고,
이미 있으면 덮어쓸지 물어본다.

## 4. 설계 결정

### 4-1. 왜 인라인인가 (요청 사항이지만, 실습에도 맞다)

- 파일 하나를 열면 **구조 · 모양 · 동작이 한눈에** 들어온다
- 경로 문제가 없다. `css/style.css` 를 못 찾아 화면이 깨지는 사고가 안 난다
- USB 로 옮겨도, 메일로 보내도 그대로 돈다
- 학생이 브라우저 개발자 도구에서 고친 값을 파일에서 바로 찾을 수 있다

대신 **중복**이라는 대가가 따른다. 이건 숨기지 않고 강의에서 다룰 주제로 삼았다
(`강의노트.md` 6차시).

### 4-2. 외부 요청을 전부 없앤 이유

"보안 이슈로 로컬에서 작업한다"는 조건을 그대로 받아들였다.
CDN 웹폰트 하나만 걸어도 폐쇄망에서는 **글꼴이 바뀌어 줄 수가 달라지고**,
강의 중에 "제 화면은 왜 다르죠"가 나온다.

| 보통 쓰는 것 | 이 자료에서 |
|---|---|
| Pretendard CDN | 안 건다. `font-family` 목록에만 올려 두고, 설치돼 있으면 쓰인다 |
| 아이콘 폰트 | 인라인 SVG (`<svg>` 를 마크업에 직접) |
| 지도 API | `<svg viewBox>` 로 그린 약도 |
| 사진 | CSS 그라디언트 + 글자 |
| favicon | `data:image/svg+xml,...` |

**결과: 5개 HTML 파일 외에 필요한 파일이 없다.**

favicon 에는 **글자를 넣지 않았다.** 탭 제목 바로 앞에 붙는 자리라
글자가 들어가면 제목과 겹쳐 읽힌다.

### 4-3. 화면을 배열로 만든다

제품 카드 18개, 게시글 18건, 대리점 11곳을 `<div>` 로 손수 늘어놓지 않았다.
**데이터 배열 하나**를 두고 스크립트가 화면을 만든다.

```js
var PRODUCTS = [
  { cat:'cattle', name:'한우 육성 프리미엄', cp:14.5, tdn:72, ... },
  ...
];
```

이렇게 하면

- 검색 · 정렬 · 분류 필터가 **자동으로 따라온다** (배열만 걸러 다시 그리면 끝)
- 실제 서버에 붙일 때 `fetch()` 결과로 배열만 바꾸면 된다
- 강의에서 "화면과 데이터를 나눈다"는 개념을 손으로 보여 줄 수 있다

### 4-4. 상태를 주소에 남긴다

제품 분류(`?cat=pig`), 게시판 쪽 번호(`?p=2`), 검색어(`?kw=채용`)를
`history.replaceState()` 로 주소에 반영한다.

새로고침해도 보던 화면이 유지되고, 링크를 그대로 공유할 수 있다.
강의 중 "이 화면 보세요" 하고 주소를 불러 줄 수 있다는 뜻이기도 하다.

### 4-5. 좁은 화면용 마크업을 따로 만들지 않는다

서브 페이지 좌측 세로 메뉴는 900px 이하에서 **네이티브 `<select>`** 로 바뀐다.
이때 select 를 HTML 에 따로 써 두지 않았다. **같은 `<ul>` 을 읽어 스크립트가 만든다.**

```js
links.forEach(function (a) {
  var op = document.createElement('option');
  op.value = a.getAttribute('href');
  op.textContent = a.textContent.trim();
  sel.appendChild(op);
});
```

메뉴가 늘거나 줄 때 한 곳만 고치면 두 모양이 같이 따라온다.

## 6. 검증

`npm run build` 같은 것으로는 화면이 맞는지 알 수 없다.
**실제 브라우저(Chromium)를 띄워 확인했다.**

### 6-1. 폭별 자동 점검

5개 페이지 × 3개 폭(360 · 768 · 1440) = 15개 조합에서 매번 확인한 것

- 스크립트 오류 · 콘솔 오류 개수
- `documentElement.scrollWidth - clientWidth` — **본문이 가로로 밀렸는지**
- 글자 크기 16px 미만인 입력 필드 개수 — **iOS 확대 방지**
- 높이 40px 미만인 버튼 개수 — **터치 대상 크기**

최종 결과:

```
✓ index      360px  overflow=0  smallInput=0  smallTap=0
✓ index      768px  overflow=0  smallInput=0  smallTap=0
✓ index     1440px  overflow=0  smallInput=0  smallTap=0
✓ about      360px  overflow=0  smallInput=0  smallTap=0
   … (15개 조합 전부)
모든 조합 통과
```

### 6-2. 상호작용 점검 (실제 클릭)


## 7. 도중에 나온 문제와 고친 내용

작업이 한 번에 된 것은 아니다. 브라우저 검증에서 잡힌 것들이다.

### 7-1. `about.html` 이 360px 에서 296px 옆으로 밀렸다

```
✗ about  360px  overflow=296
```

`.table-wrap` 으로 감쌌는데도 본문 전체가 밀렸다.

**원인:** `.sub-layout` 이 CSS Grid 인데, **grid 칸의 기본 `min-width` 는 `auto`** 다.
안쪽 표의 `min-width:640px` 만큼 칸 자체가 벌어져 버렸고,
`.table-wrap` 의 `overflow-x:auto` 는 무용지물이 됐다.

**수정:**

```css
.sub-layout > *,.grid > *{min-width:0}
```

grid/flex 안에 스크롤 영역을 넣을 때 항상 걸리는 함정이라
`강의노트.md` 에 별도 항목으로 넣었다.

### 7-2. 폼 제출 성공 메시지가 뜨자마자 사라졌다

```
올바른 폼 제출 → 클래스: form-msg      ← is-ok 가 붙어야 하는데
```

**원인:** 성공 메시지를 띄운 뒤 `form.reset()` 으로 칸을 비웠는데,
`reset()` 이 **`reset` 이벤트를 발생시킨다.** 그 처리기가
"메시지 지우기"를 하고 있어서 방금 띄운 메시지를 스스로 지웠다.

**수정:** 이번 초기화가 "제출 뒤 정리"인지 표시하고, 사용자가 직접 누른
`다시 작성` 일 때만 메시지를 지운다.

```js
clearing = true;
form.reset();
clearing = false;
...
form.addEventListener('reset', function () {
  if (!clearing) msg.className = 'form-msg';
});
```

### 7-3. 히어로 조작 버튼이 퀵메뉴 카드에 가렸다

퀵메뉴를 `margin-top:-44px` 로 히어로 위에 걸쳐 놓았는데,
슬라이더 조작 버튼이 `bottom:28px` 이라 그 44px 안에 들어가 버렸다.

**수정:** `bottom:64px` 로 올렸다.

### 7-4. 모바일에서 히어로 버튼과 조작 버튼이 겹쳤다

7-3 을 고치자 이번엔 좁은 화면에서 히어로가 짧아
`상담 신청` 버튼과 조작 버튼이 물렸다. 사각형을 실제로 계산해 확인했다.

**수정:** 900px 이하에서 히어로에 아래 여백을 준다.

```css
.hero__slide{min-height:460px; padding-bottom:112px}
```

고친 뒤 다시 계산: `히어로 CTA ↔ 조작버튼 겹침: false`

### 7-5. 스크립트가 꺼지면 본문 절반이 안 보였다

등장 애니메이션 대상(`.reveal`)은 처음에 `opacity:0` 이다.
JS 가 안 돌면 **영원히 안 보인다.**

**수정:** `<noscript>` 로 되돌린다.

```html
<noscript><style>
.reveal{opacity:1 !important; transform:none !important}
</style></noscript>
```

### 7-6. 검사 자체가 틀렸던 것 하나

`support.html` 1440px 에서 "16px 미만 입력 필드 1개"가 잡혔다.
확인해 보니 **체크박스**였다. 체크박스는 글자를 표시하지 않으므로
`font-size` 가 작아도 iOS 확대와 무관하다.

화면을 고치는 대신 **검사에서 `checkbox` · `radio` · `hidden` 을 제외**했다.
증상을 없애려고 멀쩡한 화면을 건드리지 않은 경우다.

## 8. 남은 것 / 하지 않은 것

- **원본 사이트의 실제 화면은 반영되지 않았다.** 접근이 막혀 있었다 (2장).
  강의실 PC 에서 원본을 열 수 있다면 2장 마지막의 순서대로 맞춰 갈 수 있다.
- 서버 · 데이터베이스는 없다. 문의 폼은 값을 콘솔에 찍고 끝난다.
  실습 단계상 의도한 것이며, 화면에도 그렇게 적어 두었다.
- 이미지 파일이 하나도 없다. 폐쇄망을 위해 일부러 뺐다.
  사진을 넣고 싶다면 `.prod__thumb` · `.greet__photo` 자리를
  `<img>` 로 바꾸면 된다 (`강의노트.md` 심화 과제).
- 접근성은 기본선까지만 했다 — 시맨틱 태그, `aria-*`, 키보드 조작,
  포커스 표시, `prefers-reduced-motion`. 스크린리더 실제 테스트는 안 했다.
