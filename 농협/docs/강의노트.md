# 강의노트 — 기업형 웹사이트 클론 실습

대상: 웹 프론트엔드 입문 ~ 초중급 (HTML · CSS 기본 문법을 한 번 훑은 상태)
분량: 90분 × 6차시 (조정 가능)
방식: 완성본을 먼저 보여 주고 → 뜯어보고 → 빈 화면에서 다시 만든다
환경: **로컬만.** 브라우저 하나와 편집기 하나 외에 필요한 것이 없다

---

## 0. 강의 시작 전 준비

1. `농협/` 폴더를 학생 PC 의 `D:\data\dev\농협` 에 배치
   (`setup-local.bat` 더블클릭 또는 USB 복사)
2. `index.html` 이 열리는지 확인 — 열리면 준비 끝이다
3. 편집기는 아무거나. VS Code 라면 확장 없이 그대로 쓴다

> **왜 서버를 안 띄우나**
> `file://` 로 여는 것만으로 이 자료의 모든 기능이 동작한다.
> 첫 시간에 `npm install` 로 30분을 태우지 않기 위해서다.
> 서버가 필요한 순간(`fetch`)은 6차시에 따로 다룬다.

### 첫 5분에 반드시 말할 것

이 사이트는 **실습본**이다. 실제 기업 · 제품 · 연락처와 무관하고,
화면에 나오는 문구 · 수치 · 게시글은 전부 실습을 위해 지어낸 예시다.
남의 사이트를 그대로 베껴 공개하는 일과 **화면 구성을 익히려고 따라 만드는 일**은
다르다는 것을 짚고 넘어간다. 만든 결과물을 밖에 올릴 때는
자기 문구 · 자기 이미지로 바꿔야 한다는 것도 같이 말한다.

## 1차시 — 전체 구조와 "인라인 한 파일"

### 열어 보기 (20분)

`index.html` 을 브라우저와 편집기에 동시에 띄운다.
1,300줄쯤 되지만 구조는 단순하다.

```html
<!doctype html>
<html lang="ko">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>…</title>
  <style>  /* ← 모든 CSS 가 여기 */  </style>
</head>
<body data-page="index">
  <header class="header">…</header>
  <main id="main">…</main>
  <footer class="footer">…</footer>
  <script>  /* ← 모든 JS 가 여기 */  </script>
</body>
</html>
```

**질문 던지기:** "CSS 파일도 JS 파일도 없는데 왜 이게 될까?"

### 짚을 것

| 태그 | 왜 있나 |
|---|---|
| `<meta charset="utf-8">` | 이게 없거나 늦으면 한글이 깨진다. `<head>` 맨 앞이어야 하는 이유 |
| `<meta name="viewport">` | 이게 없으면 모바일에서 데스크톱 화면을 축소해 보여 준다 |
| `<header> <main> <footer>` | `<div>` 로도 똑같이 보이지만 의미가 다르다 |
| `<script>` 가 `</body>` 앞 | 위에 두면 HTML 을 다 그리기 전에 실행돼 요소를 못 찾는다 |

### 실습 (30분)

1. `<title>` 을 자기 이름으로 바꾸고 탭 제목이 바뀌는 것 확인
2. `<style>` 안에서 `--green` 값을 `#C0392B` 로 바꾸고 저장 → 새로고침
   → **사이트 전체 색이 한 번에 바뀐다.** CSS 변수를 처음 체감하는 순간
3. `<style>` 태그를 통째로 주석 처리 → 스타일이 사라진 날것의 HTML 을 본다
   → "HTML 은 구조, CSS 는 모양"을 눈으로 확인

### 마무리 질문

"CSS 를 별도 파일로 빼면 뭐가 좋아지고 뭐가 나빠질까?"
→ 답은 6차시에 미룬다.

## 2차시 — 레이아웃: 헤더 · GNB · 히어로

### 개념 (25분)

**Flexbox** — 한 줄로 늘어놓기

```css
.header__bar{display:flex; align-items:center; gap:24px; min-height:76px}
.gnb{margin-left:auto}      /* ← 이 한 줄이 메뉴를 오른쪽 끝으로 민다 */
```

`margin-left:auto` 의 동작은 반드시 실습으로 보여 준다. `float:right` 를
쓰던 시절과 비교하면 이해가 빠르다.

**Grid** — 격자로 늘어놓기

```css
.grid-4{display:grid; grid-template-columns:repeat(4,1fr)}
```

**`position` 겹치기** — 히어로 위에 글자 얹기

```css
.hero__slide{position:relative}
.hero__inner{position:relative; z-index:1}   /* 장식 원보다 위로 */
.hero__slide::after{position:absolute; …}    /* 장식 원 */
```

### 짚을 것 — `::after` 로 장식 만들기

히어로 오른쪽 위의 큰 반투명 원은 **이미지가 아니다.**

```css
.hero__slide::after{
  content:""; position:absolute; right:-120px; top:-120px;
  width:460px; height:460px; border-radius:50%;
  background:rgba(255,255,255,.09);
}
```

이미지 없이 배경을 만드는 방법을 여기서 처음 보여 준다.
`.prod__thumb` 도 그라디언트 + 글자로 만든 가짜 썸네일이다.

### 실습 (35분)

1. GNB 에 메뉴 하나 더 추가하기 (`<li>` 복사 → 텍스트만 수정)
2. 히어로 슬라이드 4번째 만들기 — **인디케이터는 건드리지 않는다**
   → 저장하고 새로고침하면 점이 알아서 4개가 된다
   → "화면을 손으로 늘리지 않고 데이터를 늘린다"는 감각의 첫 경험
3. 히어로 그라디언트 색 바꾸기

## 3차시 — 반응형: 한 화면으로 폰부터 데스크톱까지

### 개념 (25분)

이 자료의 분기점은 셋이다.

| 폭 | 무엇이 달라지나 |
|---|---|
| ~640px | 카드가 한 열, 게시판 분류 열을 접는다, 버튼이 가로로 꽉 찬다 |
| ~900px | 상단 메뉴 → **서랍**, 좌측 세로 메뉴 → **네이티브 select** |
| 901px~ | 가로 메뉴 + 좌측 세로 메뉴(220px) + 본문 |

**모바일 우선**으로 쓰는지 데스크톱 우선으로 쓰는지 규칙을 정하고 일관되게
간다는 점을 강조한다. 이 자료는 `max-width` 기준(데스크톱 → 모바일)이다.

### 반드시 가르쳐야 하는 세 가지

**① 입력 필드 글자를 16px 아래로 내리지 마라**

```css
.input{font-size:16px}     /* 15px 로 하면 iOS 가 화면을 확대해 버린다 */
```

강사 폰으로 직접 시연하면 효과가 크다.
그래도 실수하는 경우가 있어 안전망을 걸어 두었다.

```css
@media (max-width:900px){
  input,select,textarea{font-size:16px !important}
}
```

**② 터치 대상은 44px 이상**

마우스 커서는 1px 을 찍지만 손가락은 못 찍는다.
이 자료의 모든 버튼은 `min-height:44px` 또는 `48px` 이다.

**③ 넓은 표는 표 안에서만 스크롤하게 한다**

```css
.table-wrap{overflow-x:auto}
.table-wrap > table{min-width:640px}
```

**본문 전체가 옆으로 밀리는 것**과 **표만 옆으로 밀리는 것**을
360px 화면에서 나란히 보여 준다.

### 함정 하나 — 이 자료에서 실제로 터진 버그

`.table-wrap` 을 제대로 씌웠는데도 360px 에서 본문이 296px 밀렸다.

```
✗ about  360px  overflow=296
```

**원인:** grid 칸의 기본 `min-width` 는 `auto` 라서, 안쪽 표의 `min-width:640px`
만큼 **칸 자체가 벌어진다.** 그러면 `overflow-x:auto` 는 아무 일도 하지 않는다.

```css
.sub-layout > *,.grid > *{min-width:0}     /* 이 한 줄이 해결 */
```

**Flexbox 도 똑같다** (`min-width:0` / `min-height:0`).
실무에서 반드시 한 번은 만나는 함정이라 별도 시간을 준다.

### 실습 (35분)

1. 개발자 도구 반응형 모드로 360 / 768 / 1440 을 오간다
2. `.grid-4` 의 900px 분기를 3열로 바꿔 본다
3. **일부러 깨뜨리기:** `.table-wrap{overflow-x:auto}` 를 지우고 360px 로 본다
   → 본문 전체가 밀리는 것을 확인하고 되돌린다
4. `.sub-layout > *{min-width:0}` 을 지우고 `about.html` 을 360px 로 본다
   → 위 함정을 직접 재현한다

## 4차시 — 자바스크립트 ①: 화면을 데이터로 만든다

### 개념 (30분)

`products.html` 을 연다. 제품이 18개인데 HTML 에는 카드가 **하나도 없다.**

```html
<div class="prod-grid" data-grid></div>
```

카드는 배열에서 나온다.

```js
var PRODUCTS = [
  { cat:'cattle', name:'한우 육성 프리미엄', cp:14.5, tdn:72, … },
  …
];
```

### 흐름 짚기

```
데이터(배열)
   ↓ filtered()   — 분류 · 검색어로 거르고 정렬
   ↓ render()     — 걸러진 배열로 카드를 만든다
화면
```

**사용자가 무엇을 하든 `render()` 를 다시 부르면 된다.**
탭을 눌러도, 검색어를 쳐도, 정렬을 바꿔도 마찬가지다.
"바뀐 부분만 골라 고치기"가 아니라 "상태를 바꾸고 다시 그리기" —
현대 프레임워크의 기본 발상을 프레임워크 없이 보여 주는 대목이다.

### 짚을 것

**① `escapeHtml()` 을 왜 거치나 (보안)**

```js
function escapeHtml(s){
  return String(s).replace(/[&<>"']/g, function(c){ … });
}
```

시연: 배열의 제품 이름을 `<img src=x onerror=alert(1)>` 로 바꿔 본다.
`escapeHtml` 이 있으면 글자로 보이고, 빼면 코드가 실행된다.
**"남이 넣은 값을 화면에 붙일 때는 항상 이스케이프한다."**

게시판의 검색어 하이라이트는 순서가 특히 중요하다.

```js
var out = esc(s);            // ① 먼저 이스케이프하고
… out.replace(…, '<mark>…')  // ② 그 다음 <mark> 를 붙인다
```

순서를 뒤집으면 `<mark>` 까지 이스케이프되거나, 더 나쁘게는 구멍이 열린다.

**② 디바운스 — 글자마다 다시 그리지 않기**

```js
qEl.addEventListener('input', debounce(function(){ … }, 200));
```

`debounce` 를 빼고 콘솔에 `render()` 호출을 찍어 비교하면 차이가 확 보인다.

**③ 주소에 상태 남기기**

```js
history.replaceState(null, '', location.pathname + '?cat=' + c.key);
```

새로고침해도 유지되고 링크 공유가 된다.

### 실습 (30분)

1. `PRODUCTS` 에 제품 3개 추가 → 카드 · 검색 · 정렬이 저절로 따라오는 것 확인
2. `CATS` 에 분류 하나 추가 → 탭이 저절로 생긴다
3. 정렬 기준에 "TDN 높은순" 추가 (`<option>` + `filtered()` 분기)
4. `escapeHtml` 을 잠깐 빼고 무슨 일이 생기는지 확인하고 되돌린다

## 5차시 — 자바스크립트 ②: 폼과 접근성

### 개념 (30분)

`support.html` 의 문의 폼.

```html
<form data-form novalidate>
```

`novalidate` 로 브라우저 기본 검사를 끄고 직접 검사한다.
**왜?** 기본 말풍선은 문구를 못 바꾸고, 모양도 못 바꾸고,
브라우저마다 다르게 나온다.

### 짚을 것

**① 언제 검사하나**

```js
f.addEventListener('blur',  …);   // 칸을 벗어날 때
f.addEventListener('input', …);   // 단, 이미 틀린 칸만 즉시 재검사
```

글자를 칠 때마다 빨갛게 만들면 짜증만 난다.
**한 번 틀린 뒤부터는 즉시 알려 준다** — 이 균형을 설명한다.

**② 오류가 나면 첫 오류 칸으로 데려간다**

```js
if (bad.length){ …; bad[0].focus(); return; }
```

폼이 길면 "어디가 틀렸는지" 찾다가 포기한다.

**③ 화면에 안 보이는 사람도 알 수 있게**

```js
field.setAttribute('aria-invalid', 'true');
field.setAttribute('aria-describedby', el.id);
```

```html
<p class="form-msg" role="status" aria-live="polite">
```

`aria-live` 가 붙은 곳에 글자가 바뀌면 스크린리더가 읽어 준다.

**④ 아코디언은 `<button>` 으로 만든다**

```html
<button class="acc__btn" aria-expanded="false" aria-controls="f1">
```

`<div onclick>` 으로 만들면 키보드로 못 쓴다. `<button>` 은
Tab 으로 도달하고 Enter/Space 로 눌린다 — **공짜로 얻는 것**이다.

**⑤ 애니메이션을 줄여 달라는 사람**

```css
@media (prefers-reduced-motion:reduce){
  *{animation-duration:.01ms !important; transition-duration:.01ms !important}
}
```

슬라이더 자동 재생도 이 설정을 확인하고 멈춘다.

### 실제로 터졌던 버그 — 같이 고쳐 보기

성공 메시지가 뜨자마자 사라지는 문제가 있었다.

```js
msg.className = 'form-msg is-ok';   // 성공 메시지 표시
form.reset();                        // 칸 비우기
```

`form.reset()` 은 **`reset` 이벤트를 발생시킨다.** 그 처리기가
"메시지 지우기"를 하고 있어서, 방금 띄운 메시지를 스스로 지웠다.

```js
clearing = true;  form.reset();  clearing = false;
…
form.addEventListener('reset', function(){
  if (!clearing) msg.className = 'form-msg';
});
```

**"내가 부른 함수가 이벤트를 일으킨다"**는 함정을 다루기 좋은 사례다.

### 실습 (30분)

1. 문의 폼에 "희망 연락 시간대" select 추가 (필수 아님)
2. 연락처 정규식을 고쳐 `02-123-4567` 도 통과하게 만들기
3. FAQ 항목 2개 추가 → 검색 · 모두 펼치기가 저절로 따라오는지 확인
4. 폼을 다 채우고 제출 → 개발자 도구 콘솔에서 보낼 값 확인

## 6차시 — 인라인 방식의 값과 대가, 그리고 다음 단계

### 1차시의 질문으로 돌아온다

> "CSS 를 별도 파일로 빼면 뭐가 좋아지고 뭐가 나빠질까?"

직접 세어 본다.

```bash
grep -c "" index.html        # 줄 수
```

5개 페이지에 **똑같은 공용 CSS 가 5벌** 들어 있다.

| | 인라인 (지금) | 파일 분리 |
|---|---|---|
| 파일 개수 | 1개 | HTML + CSS + JS |
| 경로 사고 | 없음 | 있음 (`css/style.css` 못 찾음) |
| 두 번째 페이지 로딩 | 매번 새로 받음 | CSS · JS 를 **캐시**에서 |
| 공용 스타일 수정 | **5곳을 고쳐야 함** | 1곳 |
| 배포 | 파일 복사 | 파일 복사 |

**결론: 규모가 작고 배포가 단순하면 인라인이 낫고, 페이지가 늘면 분리가 낫다.**
"항상 이게 정답"이 아니라 **상황에 따라 고르는 것**임을 가르친다.

### 이 자료가 택한 절충안 보여 주기

```
_build/parts/style.css   ← 원본은 한 벌만
_build/pages/*.html      ← 페이지별 조각
      ↓ node _build/build.mjs
농협/*.html              ← 합쳐진 단일 파일 (학생이 받는 것)
```

```bash
cd 농협
node _build/build.mjs
```

**"만들 때는 나눠 두고, 내보낼 때 합친다."**
Webpack · Vite 같은 번들러가 하는 일의 가장 단순한 형태다.
`build.mjs` 는 100줄이 안 되니 통째로 읽어 볼 수 있다.

### 다음 단계로 가는 길 (남은 시간)

| 하고 싶은 것 | 필요한 것 |
|---|---|
| 게시글을 진짜 파일에서 읽기 | `fetch('posts.json')` — **여기서부터 서버가 필요하다** |
| 문의를 진짜로 보내기 | 백엔드 (Node · Spring · PHP …) |
| 페이지 수십 개 | 컴포넌트 · 프레임워크 (React · Vue) |
| 검색 엔진 노출 | SSR / 정적 사이트 생성 |

`fetch` 를 `file://` 에서 시도해 CORS 오류를 **일부러 보여 준다.**
"왜 지금까지 서버가 필요 없었고, 왜 이제부터 필요한가"가 한 번에 이해된다.

```bash
npx serve .        # 또는 python -m http.server
```

## 심화 과제 (수업 밖)

1. **사진 넣기** — `.prod__thumb` 의 그라디언트를 `<img>` 로 바꾸되
   `loading="lazy"` 와 `alt` 를 반드시 붙인다
2. **다크 모드** — `@media (prefers-color-scheme: dark)` 에서
   `:root` 변수만 다시 정의한다. 화면 코드는 한 줄도 안 고쳐도 된다
   (색을 인라인으로 박지 않고 변수로 뺀 이유가 여기서 드러난다)
3. **사이트맵 페이지** — `header.html` 의 메뉴 구조를 그대로 펼쳐 놓는다
4. **JSON 분리** — `POSTS` 배열을 `posts.json` 으로 빼고 `fetch` 로 읽는다
   (서버 필요 — 6차시 마지막과 이어진다)
5. **검색 결과 하이라이트를 제품 페이지에도** — `notice.html` 의 `mark()` 를
   가져다 쓰되, 이스케이프 순서를 지킨다

## 강의 중 자주 나오는 질문

**Q. 저장했는데 화면이 안 바뀝니다**
브라우저 캐시. `Ctrl+Shift+R` (강력 새로고침).

**Q. 한글이 깨집니다**
편집기의 파일 인코딩이 UTF-8 인지 확인. `<meta charset="utf-8">` 은 이미 있다.

**Q. 개발자 도구에서 고친 게 사라집니다**
개발자 도구 수정은 메모리에만 있다. 파일을 고쳐야 남는다.
**실험은 개발자 도구에서, 확정은 파일에서.**

**Q. 이 코드를 제 포트폴리오에 써도 되나요**
실습 결과물은 자기 것이다. 다만 밖에 공개할 때는
**기관명 · 문구 · 데이터를 반드시 자기 것으로 바꾼다.**
남의 회사 이름을 단 채로 올리지 않는다.

**Q. `var` 를 쓰던데 `let`/`const` 아닌가요**
맞다. 이 자료는 오래된 브라우저에서도 그대로 돌게 하려고 `var` 와
`function` 표현식을 썼다. 강의실 PC 사정이 좋다면 `const`/`let`,
화살표 함수, 템플릿 리터럴로 바꿔 쓰는 것을 권한다 —
**그 자체가 좋은 실습 과제다.**
