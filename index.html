안전하게 자동화하는 방법

대상 시스템은 REST API가 아니라 *.dunet 서버 렌더링 웹앱입니다. 화면 탐색과 네트워크 요청 분석으로 파악한 구조와, 성적 데이터를 손상시키지 않으면서 반복 작업을 줄이는 설계를 정리했습니다.

01핵심 발견 사항

기대했던 깔끔한 REST/JSON 구조가 아니라, 예전 방식의 서버 렌더링 웹앱입니다 (Struts / JSP 계열로 추정). 모든 요청이 .dunet으로 끝나고, 대부분 GET이 아니라 POST이며, 응답도 JSON이 아니라 HTML 조각이거나 페이지 전체입니다.

항목일반적인 REST API이 LMS
URL/api/v1/courses/123/lms/myLecture/doListView.dunet
메서드자원별 GET/POST/PUT/DELETE대부분 POST (조회조차도)
응답JSONHTML 조각 또는 페이지 전체
인증Bearer 토큰 / API 키세션 쿠키 JSESSIONID
상태 확인없음 (stateless)화면마다 getSessionInfo.dunet 반복 호출

로그인은 자동화할 수 없다

로그인 화면에 슬라이더 캡차(slidercaptcha) 리소스가 존재합니다. 따라서 아이디/비밀번호 자동 제출로는 로그인이 되지 않습니다.

채택한 방식 사람이 브라우저에서 직접 로그인 → 그 시점의 세션 쿠키를 저장 → 이후 수집 작업이 그 쿠키를 재사용. 이건 우회가 아니라 캡차의 의도를 그대로 존중하는 방식입니다. "사람이 한 번 로그인했다"는 사실을 유지한 채, 그 사람이 손으로 하던 반복 조회만 대신합니다.

메뉴 이동은 링크가 아니라 폼 제출

메뉴는 href="..."가 아니라 javascript:fnGoContent(...), fncGoClassroom(...) 같은 함수 호출입니다. 이 함수들이 숨겨진 폼을 만들어 POST로 제출합니다. 즉 URL만 복사해서는 화면에 갈 수 없고, 어떤 파라미터가 폼에 실리는지를 알아야 합니다.

식별자 스키마 — 이 세 가지면 충분하다

식별자예시 (마스킹)의미
course_id202610UN0060****Y2학기(202610) + 과목코드 + 분반코드가 이어붙은 문자열
class_noY2분반코드 (Y1~Y6 형태)
user_no2024*****학생 학번
report_no + report_seq3 + 1과제 식별 (과제번호 + 회차)
학기 전환 course_id의 앞 6자리(학기)만 새 값으로 바꾸면 동일 로직이 그대로 재사용됩니다. 그래서 어떤 식별자도 코드에 하드코딩하지 않습니다. 전부 .env에서 주입합니다.

확인하지 않은 부분 — 의도적으로

개별 학생 채점 모달에 "저장" 버튼이 있고, 목록에는 "선택한 교육생의 점수 일괄 수정" 기능이 있습니다. 하지만 저장 시 호출되는 실제 POST 엔드포인트는 확인하지 않았습니다. 실제 학생 데이터를 변경하지 않기 위해 저장 버튼을 누르지 않고 모달을 닫았기 때문입니다. 이 미확인 영역이 곧 아래 아키텍처에서 쓰기를 브라우저 자동화로 처리하기로 한 이유입니다.

03아키텍처

한 문장 요약 읽기는 HTTP 클라이언트로, 판단은 AI 초안으로, 쓰기는 사람 확인 후 브라우저 자동화로.
사람

로그인

슬라이더 캡차 때문에 자동화 불가. 사람이 로그인하고 세션 쿠키를 저장해 재사용합니다.

프로그램

읽기

과제 목록·제출물·학생 명단·성적 그리드는 확인된 엔드포인트로 안전하게 수집합니다.

브라우저

쓰기

점수 저장은 직접 호출하지 않습니다. 화면을 열어 입력창을 채우고 저장 버튼을 누릅니다.

전체 흐름

왜 쓰기를 직접 호출하지 않는가

(a) 데이터 손상 위험. 저장 API의 정확한 파라미터와 서버측 검증 로직을 100% 파악하지 못했습니다. 필수 파라미터 하나를 빠뜨리거나 형식이 틀리면 성적이 0으로 덮이거나 다른 회차에 기록될 수 있습니다. 성적은 되돌리기 어려운 데이터입니다.

(b) 기관 정책. 학교 IT 정책상 비공식 API 호출이 허용되지 않을 수 있습니다. 브라우저에서 사람이 하는 것과 동일한 조작은 정책적으로도 훨씬 방어 가능합니다.

느린 게 맞다 브라우저 자동화는 API 직접 호출보다 훨씬 느립니다. 하지만 성적 데이터에서는 느린 쪽이 옳은 선택입니다.

계층 설계 — 읽기와 쓰기를 물리적으로 분리

계층책임이 계층이 절대 하지 않는 것
lms/session.ts세션 쿠키 확보·저장·생존 확인로그인 자동 시도
lms/client.ts쿠키 실어 요청, 레이트리밋, 만료 감지쓰기 요청 전송
lms/parse.tsHTML/JSON → 정규화된 객체네트워크 호출
collect/*화면별 수집 로직데이터 가공·판단
db/*로컬 저장, 원본 스냅샷 보존외부 통신
grade/*루브릭 적용, 초안 생성LMS 접근
automation/*브라우저로 점수 입력사람 확인 없이 저장

핵심은 client.ts가 조회만 가능하도록 코드 수준에서 막는 것입니다. 쓰기 경로는 오직 automation/에만 존재합니다. 실수로 섞일 수 없게 물리적으로 분리합니다.

04구현 로드맵

각 단계는 앞 단계가 끝나야 다음이 의미가 있습니다. 순서대로 진행하세요.

0
사전 확인 — 코드 작성 전
  • 접속 중인 시스템이 운영인지 데모인지 확인 (화면에 "Demo" 표기가 있었음)
  • 운영이라면 원격교육지원센터에 자동화 도구 사용 가능 여부 문의
  • 본인 담당 과목의 course_id, class_no 확보

이 단계를 건너뛰지 마세요. 여기서 "불가" 답을 받으면 이후 전부가 무의미합니다.

1
세션 확보
  • npm run auth — Playwright로 브라우저를 열고, 사람이 직접 로그인
  • 로그인 완료 후 storageState를 .auth/state.json에 저장
  • getSessionInfo.dunet 호출로 세션 생존 확인

완료 기준 — 스크립트에서 담당 과목 목록을 한 번 읽어올 수 있다.

2
읽기 전용 수집
  • 담당 과목 목록 → 학생 명단 + 평가항목/가중치
  • 과제 목록 → 학생별 제출 여부·현재 점수 → 제출물 본문·첨부
  • 모든 응답 원본을 raw_html로 함께 저장

완료 기준 — LMS에 다시 접속하지 않고도 로컬 데이터만으로 채점할 수 있다.

3
채점 초안 생성
  • 과제별 루브릭을 사람이 직접 작성 (grade/rubrics/*.md)
  • 제출물 + 루브릭 → Claude → {score, reasoning, feedback}
  • status='draft'로 저장 · 만점 초과/음수 범위 검증

완료 기준 — 초안이 로컬에 쌓인다. 아직 LMS에는 아무것도 쓰지 않았다.

4
사람 검토
  • npm run review — 초안을 제출물과 나란히 표시, 점수·피드백 수정
  • 승인 시 status='approved' + 검토 시각 기록
  • 미검토 초안은 Phase 5 진입 차단

완료 기준 — 승인된 항목만 다음 단계로 넘어간다.

5
브라우저 자동화 입력
  • --dry-run으로 먼저 전 과정 실행 (저장 버튼만 안 누름)
  • 채점 화면 열기 → 입력창 채움 → 화면 캡처 + 이전값/새값 표시 → 사람 승인 → 저장
  • 저장 후 값 재조회하여 검증 · 감사 로그 기록

첫 실행은 반드시 --limit 1로 한 명만. 화면에서 눈으로 확인한 뒤 전체를 진행하세요.

학기 전환 — 코드 변경 없음

# 1학기
npm run collect -- --course 202610UN0060****Y2 --class Y2

# 2학기 — .env 의 COURSE_ID 만 교체하면 끝
npm run collect -- --course 202620UN0060****Y2 --class Y2

06유의사항

⚠️ 운영 시스템 여부 확인 필요 조사 당시 페이지 좌측 상단에 "LMS(BLU3.0) Demo"라는 문구가 보였습니다. 이게 실제 운영 시스템인지 데모/테스트 환경인지 확인되지 않았습니다. 실제 운영 시스템이라면 자동화 전에 소속 기관 원격교육지원센터에 비공식 자동화 도구 사용이 정책상 허용되는지 확인하세요.
이 문서의 마스킹 이 저장소의 호스트명·과목코드·학번은 모두 마스킹되어 있습니다 (<LMS_HOST>, 202610UN0060****Y2, 2024*****). 실제 값은 .env에만 두고, 이 파일은 .gitignore로 제외되어 있습니다.
사용 범위 본인이 담당하는 과목의 데이터에만 사용하세요. 이 도구는 교수자가 손으로 하던 반복 조회와 채점 초안 작성을 돕는 보조 도구이며, 채점의 최종 판단과 책임은 교수자에게 있습니다.
